# 匿名利用イベントの保存・集計仕様

策定日: 2026-07-25

## 1. 採用技術

- 永続ストア: Neon Postgres
- 接続: `@neondatabase/serverless` のHTTP接続
- 接続先: `ANALYTICS_DATABASE_URL`。未設定時のみ `DATABASE_URL` を使用
- DB構造: `db/migrations/0001_anonymous_analytics.sql`

Neon Postgresを採用する理由は、Vercelのサーバレス実行環境から接続でき、イベントの重複防止、日単位の一意集計、Week 2 / Week 4集計をPostgresの制約と構造化データで扱えるためである。

## 2. 本人同意

- 初期状態は送信しない。
- 初回説明で本人が任意項目を選択した場合だけ、以後の匿名利用イベントを送る。
- 「これまで」タブから、いつでも送信を開始または停止できる。
- 停止時は `DELETE /api/events` を呼び、現在の端末・ブラウザに対応する保存済みイベントと日次集計を削除する。
- ブラウザデータ削除などで匿名IDが失われた場合は、以前のIDを指定して即時削除できない。その場合も365日で自動削除する。

本人のセルフケア記録本文は端末内保存のままで、匿名イベントDBへ保存しない。

## 3. 許可イベント

許可されていないイベント、フィールド、メタデータは `400` で拒否する。リクエスト上限は4KiBとする。

| イベント | クライアントから受ける項目 | DBに保存するメタデータ | 用途 |
| --- | --- | --- | --- |
| `record_saved` | 記録対象日 | なし | 記録利用日の日次集計 |
| `first_record_saved` | 記録対象日 | なし | 初回保存操作の確認 |
| `backup_exported` | なし | なし | バックアップ利用状況 |
| `backup_imported` | 記録件数、できること件数 | 許可した2件数のみ | 復元機能の利用状況 |
| `tab_viewed` | `today` / `records` / `selfcare` / `reflection` | 許可したタブ名のみ | 主要画面の利用状況 |

記録対象日は形式確認だけに使い、DBへ保存しない。気分、睡眠、服薬、しんどさのサイン、メモ、面談内容、氏名、連絡先、所属、研究参加者IDは受理しない。

## 4. 識別子と重複防止

- クライアントはイベントごとに `eventId` を生成する。
- `installId` と `eventId` は、サーバで `ANALYTICS_ID_SALT` を鍵にHMAC-SHA256へ変換してから保存する。
- 生の `installId` と `eventId` はDBへ保存しない。
- `event_id_hash` を主キーにし、同一イベントの再送を1回として扱う。
- `record_saved` は、日本時間のサーバ受信日ごとに1行へ集約する。同じ日の複数保存は `save_count` だけを増やす。

研究参加者ID、氏名、連絡先、所属、研究アンケートとの対応表は作らない。

## 5. テーブル

| テーブル | 内容 |
| --- | --- |
| `anonymous_analytics_events` | 許可済みイベント。不可逆化ID、イベント名、発生・受信時刻、許可済みメタデータ |
| `anonymous_analytics_record_days` | 不可逆化した端末・ブラウザ単位、日本時間の記録利用日、同日保存回数 |

`POST /api/events` はイベント挿入と日次集計更新を同一トランザクションで行う。重複イベントの場合は日次保存回数も増やさない。

## 6. 継続指標

集計単位は人ではなく、匿名の端末・ブラウザである。`record_saved` の最初のサーバ受信日を Day 0 とする。`docs/phase2-plan.md` 3.2節の主要指標5件を、すべて Day 0〜Day 27 の同じ窓で数える。窓を固定するので、集計日を後ろへずらしても同じ端末・ブラウザの値は変わらない。

- 初週複数日記録率: Day 0〜6に2日以上記録した割合
- Week 2継続率: Day 7〜13に1日以上記録した割合
- Week 4継続率: Day 21〜27に1日以上記録した割合
- 週あたり記録日数: 窓を7日ずつ4つに区切った各週の記録日数の中央値。母数は端末・ブラウザ×週で、記録が0日の週も母数に数える。0日の週を除くと、使わなかった週が見えなくなる
- 中断後再開率: 記録がない日が7日以上続いた期間があった端末・ブラウザのうち、その期間のあとに窓の中で再び記録があった割合

中断後再開率は、窓の終わりまで記録が戻らなかった場合も分母に数える。再開した側だけを分母にすると、この率は必ず100%になり、中断を失敗として扱わない設計が働いたかを判断できない。

Day 27が終わった端末・ブラウザだけを分母にする（集計日がDay 28以降）。Day 27当日に数えると、その日のうちに届いた保存で報告済みの値が後から変わる。集計ロジックは `src/lib/analytics-retention.ts` に置き、DBの日次集計から再計算できる。読み出しは `pnpm analytics:summary` で行う（8節）。

複数端末、ブラウザデータ削除、送信への不同意、送信失敗は集計上の限界として明記する。利用継続率を医学的効果の根拠として扱わない。

## 7. 保存期間と削除

- 生イベントと日次集計の保存期間は365日。
- 許可イベントの保存時に期限を過ぎた行を削除し、さらにVercel Cronで毎日削除する。新しいイベントが来ない場合も期限を超えて残さない。
- 本人が送信停止を選んだ場合は、現在の匿名IDに対応する行を即時削除する。
- 集計結果を共有するときは、少人数の個人を推測できる内訳を出さない。

## 8. 運用手順

1. Vercel MarketplaceからNeonを接続し、Functionsと同じか近いリージョンを選ぶ。
2. `ANALYTICS_DATABASE_URL`、32文字以上の `ANALYTICS_ID_SALT`、16文字以上の `CRON_SECRET` を本番環境へ設定する。
3. 接続文字列を設定した管理環境で `pnpm db:analytics:setup` を実行する。
4. ダミーイベントで、`204`、重複防止、日次集計、送信停止時の削除を確認する。
5. `/api/cron/purge-anonymous-analytics` が本番で毎日成功していることをVercelのCronログで確認する。
6. 継続指標を見るときは、接続文字列を設定した管理環境で `pnpm analytics:summary` を実行する。
7. DBへのアクセス権は、運用上必要な担当者に限定する。

継続指標の読み出しはスクリプトだけとし、アプリ側のエンドポイントは増やさない。読み出す口を2つ持つと、同じ表に対して別々のクエリと数え方ができる。実行には TypeScript をそのまま読み込める Node.js 22.18 以降が要る（集計ロジックを写し取らず、`src/lib/analytics-retention.ts` をそのまま使うため）。

出力は集計値だけで、端末・ブラウザごとの行を含めない。割合には必ず母数を添え、母数が0のときは 0% ではなく「出さない」と表示する。対象が15件未満のときは Gate 1 の判定を出さない旨を併記する（`docs/phase2-plan.md` 4節）。集計上の限界も毎回併記する。

DB設定がない、または保存に失敗した場合、APIは `503` を返す。クライアントは失敗を握りつぶし、セルフケア記録の保存を妨げない。
