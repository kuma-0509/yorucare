## 1. 全体像

事業計画1節の逆算スケジュール（試運転 → 振り返り → 無料モニター本編 → エビデンス → 個人会員募集 → 個人向けサービス開始 → 企業営業 → 企業受注）の8ステップに、アプリ側でやることを1つずつ重ねます。

| 項目 | 内容 |
|---|---|
| 支援期間 | 2026年10月〜2028年3月（18か月） |
| 募集形態 | 2期制（Season 1／Season 2） |
| 募集人数 | 各期6名（3チーム × 2名）＋ スポットレビュアー若干名 |
| 1人あたり工数 | 通しで約200時間（Season 1 約95時間／Season 2 約105時間） |
| 延べ工数 | 約1,200時間（コア6名 ＋ スポット枠） |
| 活動形態 | オンライン（Zoom）。NDA対応可 |
| 前提 | 実装は当方で行う。手を動かしていただくことは前提にしない |
| 制約 | 参加者ご本人の記録・個人情報には触れない範囲でお願いする |

18か月を1期で募集すると離脱リスクが高いため、2期に分けます。Season 2 は Season 1 のメンバーに継続を打診し、不足分だけ新規募集します（プロボノ倶楽部の前例：BANSO-CO様支援プロジェクト Season1〜3 と同じ形）。

### 期の区切り

| Season 1 | つくる・確かめる | 2026年10月5日(月)〜2027年5月28日(金) | 34週 | 約95時間 |
| Season 2 | 売れる形にする | 2027年6月1日(火)〜2028年3月31日(金) | 43週 | 約105時間 |

## 2. フェーズ別の依頼内容と工数

週工数はすべて「1人あたり」です。

### 01. 試運転・集中レビュー（2026年10月・4週／週5時間・計20時間）

事業側は試運転（1か月・最少3名）。

- いまのコードと設計を見て、「ここが一番危ない」を3つ挙げる
- クラウド保存の構成を「いま必要／後でよい／要らない」に仕分けた表1枚をつくる
- セキュリティに使える5万円を、どこに置くのが一番効くか順位をつける
- 無償で代替できる確認手順（依存の脆弱性・シークレット検出・静的解析・ヘッダ検査）の型を出す
- 3名が実際に書けているかを、何を見て判断するのかを決める

成果物：仕分け表1枚／危険箇所トップ3／5万円の使い道

### 02. 振り返り・ブラッシュアップ（2026年11月・4週／週4時間・計16時間）

事業側は試運転の振り返りと、本編21名の募集・ベースライン調査。

- 試運転3名の記録の付き方を見て、入力項目と画面の言葉を削る（言葉は `copy.ts` に集約済み）
- 10月の指摘を反映した結果を確認する（実装は当方）
- 自動チェックを GitHub Actions に組み込む（依存の脆弱性・シークレット検出・静的解析）
- 21名になると出てくる差（端末・ブラウザ・問い合わせ）を先に洗い出す
- 参加前アンケートとアプリ記録を、どう突き合わせるかを決める

成果物：改善リスト（優先順位つき）／CIチェックの構成

### 03. 本編21名の並走（2026年12月〜2027年4月・22週／週2時間・計44時間）

事業側は5か月プログラム本編（無料・21名）。

- 月1回、継続の数字を一緒に読む（初週の複数日記録率／Week 2継続率／Week 4継続率／端末を変えたときの離脱）
- 数字が落ちた月に、原因の見立てを出す
- 中間アンケート（2027年2月）に合わせて中間レビューを1回
- 不具合と改善要望に優先順位をつける（本編中は大きく変えない前提で、何を今直すかを決める）

成果物：月次の継続レポート／改善の優先順位

### 04. エビデンス・GATE判断（2027年5月・4週／週4時間・計16時間）

事業側はエビデンスづくりと、続ける／やめるの判定（事業計画7節）。

- **GATE**：21名5か月の実データで、クラウド保存に進むか、端末内保存のままで行くかを結論づける
- 進む場合、最小構成はどこまでかを設計レビューで確定する
- アプリの継続の数字を、企業に見せられる形に整理する（「効果があった」とは書かない前提で）

成果物：GATE判断の結論と根拠／進む場合の最小構成

### 05. 個人会員募集の準備（2027年6月・4週／週3時間・計12時間）

事業側は個人会員の募集（1か月）。

- 有料版に必要な最小機能の線引き（無料版と何が違うのか）
- 申込みから利用開始までの画面の流れをレビューする
- 有料である以上必要になる備え（問い合わせ、復旧手順、バックアップ、退会時のデータの扱い）を確認する

成果物：有料版の機能線引き／運用チェックリスト

### 06. 有料版リリース伴走（2027年7月・4週／週4時間・計16時間）

事業側は個人向け有料サービス開始（月5,000円）。

- 公開直後の不具合の切り分けに付き合う（最初の2週間が山場）
- お金まわりの安全確認。決済情報を自前で持たない設計にできるかを見る
- クラウド保存に進む判断だった場合、段階リリースの設計と各段階のレビュー

成果物：リリース判定／段階リリース計画

### 07. 企業向けの守り固め（2027年8月〜2028年2月・30週／週2時間・計60時間）

事業側は企業・支援機関への営業。

- **企業のセキュリティチェックシートへの回答をつくる。ここが受注の一番の関門になる**
- 産業医・情報システム部門の審査に耐える説明資料（データの流れ図、保存場所、削除、権限、委託先）
- 「人事は本人の記録を見られない」という設計を、文書として明文化する
- 商談で出た技術的な質問の持ち帰り対応（月1〜2件想定）

成果物：チェックシート回答テンプレ／データフロー図／導入企業向け説明資料

### 08. 受注・試験導入の受け入れ（2028年3月・5週／週3時間・計15時間）

事業側は企業1社からの試験導入受注（1〜3名分）。

- 試験導入1社を受け入れる初期設定とサポート手順の確認
- 導入前の最終チェック。フェーズ03〜07で先送りにしたものを棚卸しする
- 次の期に何を残すかの引き継ぎ

成果物：導入手順書／積み残しリスト

## 4. チーム編成

プロボノ募集資料で挙げている「見ていただきたい3つ」に、そのままチームを当てます。Season 2 は企業対応の比重が上がるため配分を変えます。

| チーム | 見ていただくこと | Season 1 | Season 2 |
|---|---|---:|---:|
| 安全の線引き | 5万円の使いどころ、クラウド保存の要否、企業の審査対応 | 2名 | 3名 |
| 続く形 | 書く負担、画面の言葉、調子が悪い日でも開けるか | 2名 | 2名 |
| 確かめ方 | 「続いた」と言うために、何をどう数えるか | 2名 | 1名 |
| **合計** | | **6名** | **6名** |

別枠で、単発1回・1〜2時間のスポットレビュアーを受け入れます（人数は決めない）。

## 6. 確定事項と予備プラン

### 6-1. 本編の開始月

**試運転10月＋振り返り11月＋本編2026年12月〜2027年4月で確定。**

プロボノ募集資料（アプリ版）に「実践研究 2026年11月〜・5か月」と記載されている箇所は、**「2026年12月〜」に直す必要があります。**資料を配布する前に修正します。

### 6-2. 募集が間に合わない場合（予備プラン）

フェーズ01（集中レビュー）を11月にずらし、**試運転そのものも11月に動かします。**試運転をレビューなしで走らせることはしません。以降の全ステップが1か月ずつ後ろにずれます。工数と募集人数は変わりません。

| フェーズ | 本プラン | 予備プラン |
|---|---|---|
| 01 試運転・集中レビュー | 2026年10月 | 2026年11月 |
| 02 振り返り | 2026年11月 | 2026年12月 |
| 03 本編21名 | 2026年12月〜2027年4月 | 2027年1月〜5月 |
| 04 エビデンス・GATE判断 | 2027年5月 | 2027年6月 |
| 05 個人会員の募集 | 2027年6月 | 2027年7月 |
| 06 個人向けサービス開始 | 2027年7月 | 2027年8月 |
| 07 企業・支援機関へ営業 | 2027年8月〜2028年2月 | 2027年9月〜2028年3月 |
| 08 企業から試験導入を受注 | 2028年3月 | 2028年4月 |

予備プラン適用時の期の区切り：

- Season 1：2026年11月2日(月)〜2027年6月25日(金)
- Season 2：2027年6月28日(月)〜2028年4月28日(金)

**切り替えの判断は2026年9月末に行います。**この時点でプロボノの応募が集まっていなければ、予備プランに移ります。

事業計画1節の逆算スケジュールも、予備プランに移る場合は同じだけ後ろ倒しになります（企業受注のゴールが2028年3月から2028年4月へ）。

```
メンタル不調から復職した方が夜と休日に使うセルフケア記録アプリ
「ヨルケア」(Next.js/Vercel・プロトタイプ稼働中)について、
①調子が悪い日でも書き続けられる形になっているかのUXレビュー、
```
