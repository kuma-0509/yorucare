WHAT

何を作っているか

メンタル不調を経験して今も働いている人が、気分・睡眠・お薬・しんどさのサインを 1日1〜2分で残せるセルフケア記録アプリ。

介護や夜勤の業務記録ではなく、本人のための日記です。記録は端末の中だけに保存し、運営者・勤務先・支援機関へ自動送信しません。 毎日の入力は義務にせず、書けない日があっても再開できることを設計の芯にしています。

アプリ単体ではなく、5か月プログラムの一部

週の流れの中で、アプリは「日曜の振り返りの会で話す材料」を作る役割を持ちます。

夜の運動 各20分

ストレッチ・呼吸法。カメラOFF可、座ったまま可。両方必須ではない。

原則3名、1人5分。今週の状態と来週試すことを整理する。

GATES

作る順番は、投資判断ゲートで決めている

この制作で一番時間をかけたのは、コードではなく「作らない条件」を先に決めることでした。 健康に関わる記録を扱うので、思いついた順に機能を足すと、後から引き返せなくなります。

各ゲートの数値は医学的な効果の基準ではなく、21名規模の初期検証で「次の開発費を投じるか」を揃えて判断するための内部基準です。

見出しを押すと条件が開きます。いま立っているのは Gate 1 の手前です。

Gate 0 の条件

  • 許可イベントと各フィールドが一覧化され、自由記述や入力内容を受け付けない
  • 不正形式の拒否、重複対策、保存失敗時の扱いをテストできる
  • 利用者向け説明、オプトアウト方法、保存期間、削除手順、閲覧可能者が決まっている
  • 匿名の利用イベントを、本人の記録・研究データと結合しない
  • 集計結果が少人数の個人を推測できる粒度で公開されない

Gate 1 の条件（4週間観測できた install が15以上のときだけ判定する）

指標 継続投資の基準
初週複数日記録率60% 以上
Week 2 継続率50% 以上
Week 4 継続率35% 以上
基本記録の2分以内完了5人中4人以上

未達でも重大不具合がなければ「改善して再検証」。原因に対応する変更を1つだけ行い、同じ定義で測り直す。

Gate 2 の条件

継続率が低いという理由だけでは実装しない。非継続理由の上位に「忘れる」「始めるきっかけがない」があり、 確認できた回答の 30% 以上に該当する場合だけ、最小構成を検証する。 責める表現、症状を推測する表現、入力を強制する表現は使わない。

Gate 3 の条件（すべて満たしたときだけ）

  • Gate 1 の継続投資基準を満たす
  • 端末変更・データ消失・複数端末利用が、3人以上または確認対象の15%以上で阻害要因になっている
  • 認証、アクセス制御、保護、バックアップ、保存期間、本人による削除、権限、インシデント対応が文書化されている
  • 参加説明・同意・研究手続きへの影響確認が完了している

満たさない間は、端末保存と本人操作によるバックアップを維持する。

Gate 4 の条件（すべて満たしたときだけ）

  • 週次まとめのタスクテストで、5人中4人以上が内容を理解し、共有前に期間と項目を確認できる
  • 5人以上から、自分で選んだ相手へ共有したいという明示的な需要が確認できる
  • 初期状態が非共有で、相手・項目・期間・有効期限・取り消し・閲覧権限を本人が選べる
  • 勤務先や支援機関への自動共有、常時監視、本人の知らない二次利用を行わない
AI BOUNDARY

AIには「何を渡さないか」から決めた

渡してよいもの

  • ○集計値記録日数、就寝時刻の中央値など
  • ○選択式のタグしんどさのサインなど、選択肢から選んだもの
  • ○辞書のタイトル「できること」として本人が登録した項目名

端末の中にとどめるもの

  • ×本人が書いたメモ本文一番デリケートで、一番集計に要らない部分
  • ×記録の全文端末外へ出す経路をそもそも作らない
  • ×書き込み・削除の手段ツールは読み取り専用。確定は本人のボタン操作だけ

この方針で大事なのは、運用ルールで守らないことです。 ツールの戻り値の型に本文のフィールドをそもそも持たせないので、うっかり渡すコードが書けません。

気をつけようと決めるのではなく、間違えられない形にする。ここが一番学びになった部分です。

文章の作り方：数値はアプリ、つなぎの言葉だけLLM

数値をLLMに書かせると、健康の記録では誤りが致命的になります。そこで穴埋め方式にしました。

アプリが確定させる数値 LLMが書く文章の穴

この7日間のうち、記録があったのは 5日 でした。 記録できた日をふりかえると、就寝時刻の中央値は 24:30、 「しんどさのサイン」で多かったのは 頭が重い（3日 / 5日）です。 来週の振り返りでは、この2つを見てみるのがよさそうです。

表示例です。LLM呼び出し自体はまだ未実装で、設計と集計側だけが完成しています。 数値には必ず母数（3日 / 5日）を添え、割合では示しません。「達成率60%」は、できなかった側を強調してしまうためです。

0件は 0 ではなく null

「値が低い」と「データがない」を区別する。書けなかった日を、状態が悪かった日として扱わない。

相関を因果に読ませない

差分の戻り値は、効果ではなく事実だけを述べるキー名にする。片側の日数が少なければ差分を返さない。

週次まとめは、あえてLLMを使わない

毎週読むものは、言い方がぶれないほうが本人にとって安心。速く、無料で、毎回同じ言葉になる。

1分で話すこと

読み上げ用 · 約360字 · 3段落で約60秒

ヨルケアという、メンタル不調を経験して今も働いている人向けの、セルフケア記録アプリを作っています。気分・睡眠・お薬・しんどさのサインを1日1〜2分で残して、日曜の振り返りの会で自分の状態を話す材料にする、という使い方です。

今は Phase 1 を Vercel で公開して、スマホで実際に使える状態です。この1か月は、機能を増やす前に何を検証するかを先に決めて、匿名の利用計測の永続化、相談窓口の常設、直近7日の週次まとめ、本人が選んだ項目だけを共有テキストにする機能まで実装しました。テストは155件で、CI で lint・テスト・ビルドが通っています。

苦戦しているのは AI の入れ方です。健康の記録なので、数値はアプリ側で確定させて、文章の穴だけを LLM に書かせる穴埋め方式にしました。次は、スマホ実機テストと、4週間の継続率の観測です。
