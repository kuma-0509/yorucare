# 本人選択による共有の導入判断と最小構成

決定日: 2026-07-27  
状態: 本人操作の端末内テキスト共有を実装・対人共有はGate 4まで保留

## 1. 結論

15名の非商用フィードバック期間には、特定の生成AI APIへの自動送信、対人共有リンク、週次まとめの自動送信を本番実装しない。現在の5か月間プログラムで確定している「本人端末内へ保存し、本人が必要に応じて自分で見せる」という境界を維持する。

一方で、本人が自分の記録を持ち出して自分で選んだ生成AI等へ渡せるよう、最大7日間の選択項目を端末内でプレーンテキスト化する機能を提供する。本人が全文を確認して確認欄を選んだ後だけ、OSの共有シート、クリップボード、`.txt`保存を利用できる。ヨルケアのサーバーや特定AI APIへは送信しない。

対人共有は次の二段階で検証する。

1. 週次まとめの実装後、ダミーデータを使った「この画面を見せる」提示モードで、本人が対象期間と項目を確認・選択できるかをテストする。
2. Gate 3とGate 4を両方満たした後だけ、期限付き・閲覧専用スナップショットのリンク共有を実装する。

JSONバックアップは全記録と自由記述を含み得るため、共有用成果物として扱わない。対人共有のために、メール添付、SNS、メッセージアプリへ記録ファイルを直接送る機能も初期対象外とする。

## 2. Gate 4の現在地

| 条件 | 2026-07-27時点 | 判断 |
| --- | --- | --- |
| 5人中4人以上が週次まとめを理解し、共有前に期間・項目を確認できる | 週次まとめが未実装で、タスクテスト未実施 | 未達 |
| 5人以上から本人が選んだ相手へ共有したいという明示需要がある | 15名への需要確認が未実施 | 未達 |
| 相手、項目、期間、有効期限、取り消し、閲覧権限を本人が選べる | 対人共有の要件を本文書に確定。本人操作の端末内テキスト共有のみ実装 | 一部実装 |
| 自動共有、常時監視、本人の知らない二次利用を行わない | 現行アプリは端末内保存・非共有 | 維持 |

したがって、現時点の判断は「最小構成を確定し、共有の本番実装は保留」である。

## 3. 共有需要の確認方法

15名へのフィードバックでは、氏名、共有相手の氏名・所属、記録内容、相談内容を収集しない。週次まとめのダミー画面を確認した後、次の固定選択だけを尋ねる。

質問:

> この週のまとめを、自分で選んだ相手に見せたいと思いますか。

- 自分の端末画面を、その場で見せたい
- 期限付きの閲覧リンクで見せたい
- 自分で見返すだけでよい
- 共有したくない
- まだ分からない
- 回答しない

補助質問:

> 見せる場合、どの種類の相手を想定しますか。（複数選択可）

- 医療・相談の担当者
- 支援の担当者
- 家族など身近な人
- その他の本人が選んだ相手
- 回答しない

判定規則:

1. 最初の質問で提示モードまたは期限付きリンクを選んだ人を、明示需要ありと数える。
2. 明示需要が5人以上あることをGate 4の需要条件とする。
3. 相手の種類は設計の補足にだけ使い、氏名、組織名、関係の詳細は収集しない。
4. この回答を医学的効果、支援の必要性、危機の有無の判断へ使用しない。

## 4. 第1段階: 端末内の提示モード

週次まとめ実装後の最初の検証は、サーバー送信、リンク生成、ファイル生成を行わず、本人端末上だけで完結する。

1. 初期状態は非共有とし、通常の週次まとめに共有ボタンや共有中表示を出さない。
2. 本人が「この画面を見せる」を選んだ後、対象週と表示項目を選ぶ。
3. すべての項目を初期状態では未選択とし、1項目以上を本人が選ぶまで提示を開始できない。
4. 確認画面で、実際に表示される内容だけをプレビューする。
5. 最終確認後、操作ボタンや他の週への導線を隠した閲覧専用画面を表示する。
6. 10分経過、ブラウザのバックグラウンド移行、画面を閉じる操作のいずれかで提示モードを終了する。
7. 終了後に表示項目を保持せず、通常の非共有状態へ戻す。

提示モードでも、相手による写真撮影や画面の記憶をアプリから取り消すことはできない。有効化前にその点を本人へ短く説明する。

## 5. 対人共有の初期版で選択できる項目

共有対象は、完成後の週次まとめから生成した集約情報だけとする。日々の記録本文をそのまま並べない。

| 項目 | 初期値 | 初期版での扱い |
| --- | --- | --- |
| 対象期間 | 必須 | 1週間を明示する |
| 記録した日数 | 未選択 | 選択可能 |
| 状態の推移 | 未選択 | 数値・定型ラベルの推移だけ選択可能 |
| 睡眠時間の推移 | 未選択 | 時刻ではなく時間量の推移だけ選択可能 |
| セルフケアを行った日数 | 未選択 | 回数だけ選択可能 |
| 本人が選んだ短い相談メモ | 対象外 | 初期版では共有しない |
| 服薬状況 | 対象外 | 初期版では共有しない |
| しんどさのサイン、タグ、メモ | 対象外 | 初期版では共有しない |
| カスタム状態ラベル | 対象外 | 初期版では共有しない |
| セルフケア名、セルフケアメモ | 対象外 | 初期版では共有しない |
| 日々の自由記述 | 対象外 | 初期版では共有しない |
| JSONバックアップ | 対象外 | 共有成果物にしない |

相談材料として不足する場合も、初期版の対象を自動で広げない。追加項目は、本人の明示需要と安全要件を別途確認してから1項目ずつ検討する。

### 5.1 本人が使う生成AI等へのテキスト共有

対人共有リンクとは別に、本人のデータ持ち出し操作として次を実装する。

| 領域 | 実装内容 |
| --- | --- |
| 形式 | スマートフォンと生成AIで扱いやすいUTF-8プレーンテキスト |
| 期間 | 本人が選んだ開始日から終了日まで。最大7日間 |
| 初期選択 | 気分・状態、睡眠 |
| 追加選択 | セルフケア、服薬、しんどさのサイン、自由記述 |
| 確認 | 実際に共有される全文を表示し、確認欄を選ぶまで共有操作を無効化 |
| 主操作 | Web Share APIによるOS共有シート。本人が共有先の生成AI等を選ぶ |
| 代替操作 | テキストのコピー、`.txt`ファイル保存 |
| データ経路 | 端末内で生成し、ヨルケアのAPI、DB、匿名分析へ送信しない |
| AI向け指示 | 推測しない、診断・治療・処方・危機判定を行わない、事実・傾向・質問を分ける、未入力を責めない |

セルフケア、服薬、しんどさのサイン、自由記述は初期状態を未選択とし、画面上で「内容をよく確認」と示す。生成された本文には氏名等の自動除去を行わない。機械的な除去で安全だと誤認させず、本人が全文を確認する。

共有先での保存、学習利用、履歴、削除は各サービスの設定と規約に従い、共有後はヨルケアから取り消せないことを共有前に表示する。AIの回答をヨルケアへ自動で取り込まず、AIの出力を診断・治療・処方・危機判定として扱わない。

## 6. 第2段階: 期限付き閲覧リンク

リンク共有は、本人記録の一部をクラウドへ新たに保存するため、`docs/account-cloud-storage-decision.md`のGate 3と本書のGate 4を両方満たすことを実装条件とする。

| 領域 | 最小構成 |
| --- | --- |
| 作成者 | ログイン済みの本人だけ |
| 共有単位 | 本人がプレビューで確定した1週間・選択項目の固定スナップショット |
| 相手 | 1スナップショットにつき、本人が選んだ1人を想定。相手の氏名・所属は保存しない |
| 認証 | 推測困難な共有リンクと、別経路で渡すアクセスコードの組み合わせ |
| 権限 | 閲覧専用。編集、元記録への移動、別週の取得、JSON取得を許可しない |
| 有効期限 | 初期値24時間。1時間、24時間、7日から本人が選び、7日を上限とする |
| 取り消し | 本人が共有一覧からいつでも即時失効できる |
| 再共有 | システム上の再共有ボタンを設けない。ただし閲覧者の画面撮影や転送を技術的に完全には防げないことを表示する |
| 閲覧履歴 | 本人には閲覧済みか、最終閲覧時刻、閲覧回数だけを示す。閲覧者のIPアドレスや端末情報は示さない |
| 自動終了 | 期限到来、本人による取り消し、本人アカウント削除のいずれかで失効・削除する |

Web Share APIを使用する場合も、共有するのはリンクと期限の説明だけとし、健康情報やアクセスコードを同じ共有操作へ含めない。Web Share API非対応時はリンクのコピーだけを提供する。

リンクとアクセスコードの所持は、想定した相手本人であることを証明しない。両方を受け取った人は閲覧できることを作成前に説明する。相手本人の厳密な確認が必要になった場合は、閲覧者アカウント等の別要件として扱い、初期版へ追加しない。

## 7. データ境界と保護

共有スナップショットは、元の本人記録と匿名分析から論理的に分離し、匿名分析DBへ保存しない。

- 本人記録用DB内の専用テーブルと専用RLSポリシーを使用する。
- 本人が選択した集約項目だけを、スナップショット作成時に新しいデータとして固定する。
- 元記録のID、自由記述、服薬、サイン、カスタムラベルをスナップショットへ含めない。
- `shareId`とアクセストークンは256ビット以上の暗号学的乱数から生成し、トークンの原文をDBやログへ保存しない。
- スナップショット本文は本人記録と別のデータキーでAES-256-GCM暗号化する。
- 共有ページとAPIは`Cache-Control: no-store`、`Referrer-Policy: no-referrer`、検索エンジンの`noindex, nofollow`を設定する。
- 共有ページへ匿名分析、広告、外部AI、第三者スクリプトを読み込まない。
- 運用ログには本文、共有URL、トークン、アクセスコード、元記録IDを残さない。
- アクセスコード試行をレート制限し、一定回数の失敗で共有を一時停止する。

アクセス制御だけでなく、本人が共有対象を最小化できることを優先する。共有ページは診断、治療、処方、危機判定、常時監視を行わず、その代替であるとも表示しない。

## 8. 削除と期限切れ

- 取り消しと期限到来は、新しい閲覧を即時拒否する。
- ライブDBのスナップショット、トークン検証値、閲覧集計を24時間以内に削除する。
- スナップショット専用データキーを同時に削除し、暗号化バックアップ内の本文を復号不能にする。
- バックアップ残存は最長30日とし、復元時に失効・削除済み共有を再適用する。
- 共有リンクを再有効化せず、必要な場合は本人が内容を再確認して新しい共有を作る。
- 本人の元記録は、共有の失効によって変更・削除しない。

## 9. 画面要件

共有開始前に、次を一画面で確認できるようにする。

- 対象週
- 選択した項目と実際の表示内容
- 共有方法
- 想定する相手は本人が選んだ1人であること
- 有効期限
- 取り消し方法
- 相手が写真撮影、コピー、転送した内容までは取り消せないこと
- 運営者、勤務先、支援機関へ自動共有されないこと

「共有する」を主操作にせず、「内容を確認する」から開始する。取り消しは共有一覧の最上部から2操作以内で完了できるようにする。

生成AI等へのテキスト共有では、「共有する全文を確認する」を最初の操作とする。全文プレビュー後の確認欄を選ぶまで、共有シート、コピー、保存をすべて無効にする。Web Share API非対応時は、コピーと`.txt`保存だけを表示する。

## 10. 実装開始条件

### 提示モード

1. 端末内で完結する週次まとめが実装され、ダミーデータの表示テストが通る。
2. 5人中4人以上が、補助なしで対象週・項目を確認して提示を開始・終了できる。
3. 5人以上から本人が選んだ相手へ見せたいという明示需要が確認できる。
4. iPhoneとAndroidで、背景移行と10分経過による終了を確認できる。

### 期限付きリンク

1. 提示モードの条件に加えて、Gate 3とGate 4をすべて満たす。
2. 参加説明、同意、研究・安全管理手続きへの影響確認が完了する。
3. 保存国、再委託先、暗号鍵、権限管理、削除、バックアップ、事故対応を承認する。
4. ダミーデータで、作成、閲覧、コード失敗、期限切れ、取り消し、削除、バックアップ復元をテストする。
5. 本人向け説明と閲覧者向け説明がレビュー済みである。

## 11. 受入テスト

- 初期状態で共有中のデータと有効なリンクが0件である。
- 生成AI等への共有テキストは、選んだ7日以内・選んだ項目だけを含む。
- 服薬、しんどさのサイン、自由記述は、本人が選ばない限りテキストへ含まれない。
- 全文確認前は、共有シート、コピー、保存が無効である。
- テキスト生成とプレビューだけでは、ネットワーク送信や匿名分析イベントが発生しない。
- Web Share API非対応時もコピーと`.txt`保存を選べる。
- 項目未選択では提示・リンク作成を開始できない。
- プレビューと提示画面・共有スナップショットの内容が一致する。
- 対象外項目と別の週がレスポンスやHTMLへ含まれない。
- 共有作成後に元記録を変更しても、確定済みスナップショットが黙って変わらない。
- 他の本人が共有の作成、一覧、取り消しを行えない。
- リンクだけ、またはアクセスコードだけでは閲覧できない。
- 期限切れと取り消し後は、既に開いていた画面の再取得も失敗する。
- 閲覧ページのブラウザキャッシュ、参照元、検索インデックス、分析イベントへ内容が残らない。
- 同じ取り消し・削除要求を再実行しても安全に成功する。
- 提示モード終了後に、選択内容や提示画面が残らない。
- 画面撮影や転送を完全には防げないという説明が、共有開始前に確認できる。

## 12. 採用しない方式

| 方式 | 採用しない理由 |
| --- | --- |
| 勤務先、支援機関、医療者への自動送信 | 本人の選択と現在の非共有境界を失うため |
| JSONバックアップの共有 | 全記録、自由記述、服薬等を過剰に共有する可能性があるため |
| 期限のない公開URL | 転送、検索、長期残存の危険を抑えられないため |
| URLだけで閲覧できるリンク | 誤送信時にリンクを得た人が直ちに閲覧できるため |
| 閲覧者のメールアドレス収集 | 初期検証で新しい個人情報と認証運用を増やさないため |
| PDF・画像の自動保存 | 取り消し不能な複製を端末や共有先へ残しやすいため |
| 特定の生成AI APIへの自動送信 | 送信先、保存、学習利用、削除を本人が共有操作ごとに選べず、端末内保存の境界を広げるため |
| 外部AIによる共有文の自動生成 | 本人記録の自動送信と内容変換の判断が別途必要なため |
