# 当事者アンケート（第2弾）

確定日: 2026-08-17
状態: 公開済み（Google フォームを正本とする）

## 1. 目的

卒業制作と都知事杯の提出に向けて、当事者の声を集める。用途は次の2点に限る。

1. 次に実装する機能の優先順位を決める材料にする
2. 課題の実在を示す提出資料の根拠にする

この回答を、医学的効果、支援の必要性、危機の有無の判断へ使用しない（`docs/sharing-decision.md` 60行、`docs/reminder-decision.md` 36行）。

## 2. 正本の所在

**設問の正本は Google フォームの実物とする。** 本書はその写しであり、両者が食い違った場合はフォームを正とする。設問を変更したときは、本書も同じ作業内で更新する。

- フォーム: https://docs.google.com/forms/d/e/1FAIpQLScE05WHQSZKGep-p-I1V14lXVwXLFsGgSdOeUuCsfOPmf5Q4w/viewform
- 構成: 2ページ（1ページ目＝アプリ以外、2ページ目＝アプリ）
- 回答時間の目安: 3〜4分
- 設問数: 選択式9問＋自由記述1問

## 3. 位置づけ

第1弾（30名）とは設問が異なるため、**合算しない**。第2弾として別に集計する。

Q3・Q5・Q6・Q7・Q8・Q9 は必須設問だが、いずれにも「回答しない」の選択肢を置いている。`docs/reminder-decision.md` 16行の「回答しない選択も認める」を、選択肢の側で満たす形とした。

## 5. 集計と判定

### 5.1 リマインド需要（Q4）

原典: `docs/reminder-decision.md` 20〜34行。

- 分母: 「回答しない」以外を1つ以上選んだ回答
- 分子: 「忘れていた」または「始めるきっかけがなかった」を選んだ回答。同一人が両方選んでも1と数える
- 目安: 30%以上でリマインド実装着手の材料とする

**集計上の注意:** フォームでは Q3 から Q4 への分岐を設けていないため、Q3 で「記録したことはない」または「覚えていない」を選んだ回答も Q4 を目にする。**この2つを選んだ回答は Q4 の分母から除外する。** 記録を試したことがない人の「当てはまるものはない」を、記録が続かなかった人の回答と同じ母集団に入れないため。

### 5.2 共有需要（Q8）

原典: `docs/sharing-decision.md` 30〜60行。

- 条件クリア: 「自分の端末画面を、その場で見せたい」または「期限付きの閲覧リンクで見せたい」を選んだ回答が5件以上

**集計上の注意:** 「週のまとめを見ていない」を選んだ回答は分母から除外する。`docs/sharing-decision.md` 32行が、この需要確認を「週次まとめの画面を確認した後に聞く」ことを前提としているため。

### 5.3 判定の効力

Q4・Q8 の判定基準は、本来「15名の実利用者フィードバック」を対象として定義されたものである。本アンケートの回答者は実利用者とは限らないため、**結果は参考値として扱い、Gate 2・Gate 4 の正式判定には用いない。**

### 5.4 機能の優先順位（Q9）

選択肢は `docs/DEVELOPMENT_BOARD.md` の未着手項目に対応する。

| 選択肢 | 対応する課題 |
| --- | --- |
| 状態に合うセルフケアの提案 | 記録した状態から実行しやすいセルフケア行動へつなげる仕組みが不足している |
| 続けた日数や積み重ねの表示 | 継続や積み重ねを実感しにくくモチベーションを保ちにくい |
| 決めた時間のお知らせ | Gate 2通過後のリマインド機能が未実装 |
| 別の端末から利用 | アカウントとクラウド保存（Gate 3まで保留） |
| 通院や面談で使いやすいまとめ | Gate 4通過後の対人共有用期限付きリンクが未実装 |

「別の端末から利用」の選択率は、クラウド保存の需要を測る間接的なシグナルにはなるが、Gate 3 条件2（`docs/phase2-plan.md` 103行）の判定には用いない。同条件の確認は実利用者15名のフィードバックとして別途行う。

## 6. データ境界

収集しない項目:

- 診断名、お薬の名前や用量、通院先の医療機関名、勤務先名
- 共有相手の氏名・所属・関係の詳細（`docs/sharing-decision.md` 32行、59行）
- 記録本文、画面のスクリーンショットの提出（`docs/account-cloud-storage-decision.md` 17行）

禁止事項:

- 回答を、研究参加者ID・`installId`・氏名・連絡先・所属と結合しない（`docs/phase2-plan.md` 29行、`docs/account-cloud-storage-decision.md` 62〜67行）
- 希死念慮を含む尺度（PHQ-9 等）は使用しない。`docs/evidence/yorucare-5month-program-spec.md` 254〜266行が定める安全確認体制7点を確定するまで使用しないと明記されている
- 回答内容を `docs/DEVELOPMENT_BOARD.md` に記載しない（同ファイル5行）

自由記述（Q10）の扱い:

- Gate の判定には使用しない
- 提出資料で引用する場合は、個人が特定されない形に一般化してから行う

## 7. 未反映の事項

次の2点は、設計時に想定していたが公開版のフォームには入っていない。

1. **緊急時の案内文が説明欄にない。** `docs/evidence/yorucare-5month-program-spec.md` 224〜226行は次の文言をアンケートに明示すると定めている。

   > 回答や記録はリアルタイムには確認されません。緊急の相談や支援が必要な場合は、このアプリやアンケートを使用せず、医療機関や緊急サービスへ直接連絡してください。

   公開中のフォームに後から追記できるため、説明欄または最終ページへの追加を検討する。

2. **共有相手の種類を尋ねる補助設問がない。** `docs/sharing-decision.md` 30〜60行では、Q8 に続けて「見せる場合、どの種類の相手を想定しますか」（医療・相談の担当者／支援の担当者／家族など身近な人／その他の本人が選んだ相手／回答しない）を置くことになっている。Q8 単独でも需要条件の判定は成立するが、共有機能の文面や項目選択を設計する材料は得られない。必要になった時点で追加する。
