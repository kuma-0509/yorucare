### 実機テストを実施するときに必ず守ること

- **B-0 は参加者1人につき1回しか測れない。** 一度やり方を見た人は「初めて触る人」に戻せず、対象は5人しかいない。**B-0 より先に B-1 以降を参加者に見せると、その人ぶんの Gate 1 判定根拠は作り直せない。** チェックリストの冒頭とB章に同じ趣旨を3か所書いてある。消さないこと。
- **集計に入れてよいのは B-0 の1回目だけ。** 実施者が押す場所を教えたら「補助あり」として、2分以内の人数に数えない。
- **参加者に実施してもらうのは B-0 だけ**という構成にした。全項目35〜45分を5人に通してもらう想定ではない。B-1以降は実施者が1人で通す。
- **参加者を入れ替えるときは、ブラウザの設定からサイトのデータを削除する。** `deleteAllRecords`（D-8c）は `STORAGE_KEYS.records` だけを消すので、初回バナー（`storageNoticeDismissed`）、できることの一覧、復職日、演出の履歴が残る。D-8c だけでは初回の見え方に戻らず、2人目以降の計測条件が1人目と変わってしまう。
- K章は「入力内容を書かない」前提のまま。メモ本文、目標の文面、選んだ気持ち、しんどさの自由記述、感想を書かない。B-0d（手が止まった場所）も画面と操作だけを書く。
- 公開URL（https://yorucare.vercel.app）にP1機能が反映されているかは**未確認のまま**。実機テストの前にフッターの更新日付（A-8）で最新版か必ず見ること。古い版を触ると追加した確認項目がすべてNGになる。

### 今回確認した実装の事実（次のチャットが読み直さなくて済むように）

- `CompletionChoice` のフェーズは `choosing / shelf / paper / burn / done`。`footer`（「これまでの記録を見る」「今日の記録を編集する」「閉じる」）は `done` でのみ描画される。
- 選択肢の画面へ戻す方法は「編集 → 再保存」だけ。`showSaved` が false になると `CompletionChoice` がアンマウントされ、再保存で `phase: "choosing"` から始まる。同じ日の記録は上書きなので、繰り返しても記録は増えない。
- `weekly-summary.ts` の `buildLines` は行ごとに別の母数を使う。気分＝`mood.scoredDays`、睡眠時間＝`sleep.measuredDays`、就寝時刻＝`sleep.bedtimeDays`、服薬＝`medication.answeredDays`、サイン＝`warning.answeredDays`、目標＝`goalReview.answeredDays`。**前の3つは画面上どれも「記録した○日分」と表示されるが、別々の数**である。
- `exportPayloadSchema.returnDate` は `calendarDateSchema.nullable().default(null)`。フィールドを持たない書き出しも読め、`applyImport` が `saveReturnDate(null)` で端末の復職日を未設定へ戻す。`EXPORT_VERSION` は 1 のまま。
