- DEVELOPMENT_BOARD.md「週次まとめに目標の達成状況を含められない」

- 行の形は既存の服薬の行に合わせた。「できた N日」を必ず出し、「一部できた」は0日より多いときだけ添え、「できなかった」は項目として並べない。母数は `note` に「ふりかえったK日分」として置くので、本人は残りを自分で読み取れる。割合（達成率）は出さない。
- 母数は「記録があった日数」でも「目標を決めた日数」でもなく「ふりかえりを選んだ日数」とした。目標を決めたがふりかえらなかった日を「できなかった」側へ寄せないため。ふりかえりを選んだ日が0日なら行自体を出さない。
- 行の位置は「しんどさのサイン」と「続けて記録できた日」の間に置いた。状態の項目を先に並べ、目標の項目を挟み、記録の連続日数を最後にする並びにするため。
- `DailyRecord` は変更していないため、`STORAGE_SCHEMA_VERSION`（2）と `EXPORT_VERSION`（1）は据え置き。スキーマ移行も不要。

- マージ後に `docs/ai-consent-decision.md` の記述が古いままだったことが分かり、別PRで3箇所を修正した（1節の本文フィールドの列挙、3節の送ってよいもの／送らないものの表、6節「目標達成状況は含めない」の節）。いずれも `DailyRecord` に目標フィールドがない前提で書かれていた。**LLM呼び出しを実装するときは、修正後の3節の表を前提にすること**（`goalReviewStatus` は渡す、`tomorrowGoal` は渡さない）。
- `DailyView`（`src/lib/ai/daily-view.ts`）には `goalReviewStatus` を追加していない。選択式なので方針上は渡せる値だが、今回の依頼は週次まとめの集計と表示に限られており、日次ビューの利用側を確認せずに戻り値型を広げないことを優先した。必要になった時点で利用側と併せて判断する。
- `src/lib/ai-share-text.ts`（本人が全文確認して自分で渡すテキスト）にも目標は追加していない。2件目の判断を維持している。共有項目を増やすと選択UIと確認手順に影響するため、必要になった時点で別途判断する。
- 週次まとめの行の並べ方には「できなかった側を項目にしない」という既存ルールがある（服薬の行と `weekly-summary.test.ts` の「忘れた日数を項目として並べない」）。目標の行もこれに合わせたため、すべて「できなかった」だった週は「できた 0日」と表示される。この表示は服薬と同じ挙動で、テストでも固定している。表現を変える場合は服薬側と揃えて判断すること。
- `WeeklySummaryCard` の空状態テストは、画面に「0日」「達成率」等が出ないことを本文全体で確認している。記録が0件なら目標の行は出ないため両立するが、空状態の表示を変える場合はこのテストに影響する。
