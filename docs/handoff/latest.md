### 直した中身（4件）

#### 1. 棚に収めた本の非均一スケールが、軸を取り違えていた

- 棚姿勢は Y軸まわりの90°回転なので、**本のローカルX（幅 2.85）が棚の奥行きへ、ローカルZ（厚み 0.5）が背表紙の幅へ回る。** ところが `computeShelfScale` は幅を背表紙の幅で、厚みを奥行きで割っていた。
- 結果、**収まった本はワールドで 0.056 × 0.75 × 1.25** になっていた（スロットは 0.18 × 0.68 × 0.32）。**背表紙が紙のように薄いまま、棚から手前へ 1.2 も飛び出す。** 撮ったフレームでも、棚の前に薄い板が1枚立って下へはみ出していた。
- 割る辺を入れ替え、**背表紙のふくらみ（`BOOK.t * 0.96`）を奥行きに含めて**スロットにそろえた。ふくらみのぶん中心が手前へずれるので、`shelvedDepthOffset()` で奥へ戻す。

#### 2. 背表紙が棚の奥を向いていた

- `SHELF_POSE.rotationY` が `-π/2` だったため、**ローカル -X にある背表紙がワールド -Z（棚の奥）を向き、手前にはページの小口が来ていた。** 背表紙のラベルも奥を向いていた。`+π/2` に直し、ラベル側の回転も `-π/2` にして相殺した。
- 「背表紙を見せる」段の角度（`SPINE_POSE.rotationY`）も、**この段のカメラ（右手前）に対して背表紙が正面へ来る 2.3 rad** にした。従来の `-1.05` は逆向きで、**この段はずっと小口か表紙しか映っていなかった。**

#### 3. 背表紙の金装飾が、ふくらみの箱の中に埋まっていた

- 金線・帯・題箋は**ふくらみの「中心」を基準に置かれていた**が、ふくらみは幅 `BOOK.t` の箱なので、外面はさらに半分先にある。**全部が箱の内側にあって1つも見えていなかった。**
- 外面（`SPINE_FACE_X`）を基準に置き直した。題箋は**金を縁として後ろに、暗い革の札を前に**重ね（逆だと札全体が金の板になって日付が読めない）、日付のラベルはその上に載せた。真ん中の金線は題箋と重なるので落とし、上下の2本と帯だけにした。

#### 4. 縦長の画面で、書いた行と本が画面からはみ出していた

- 透視投影で横に見える幅は `2 * 距離 * tan(画角/2) * 縦横比`。**390×844 では、筆記の段の見える幅が 0.71 しかないのに、行を入れている要素の世界幅は 0.74 あった。** 撮ったフレームでは **各行の頭が左端で切れていた**（「6月18日（木）」→「18日（木」）。
- **カメラを引いて直す方法は採らなかった。** 霧が 3.6 から立ち上がるので、行が収まる距離まで引くと本が背景へ沈む。**文字の側を縦横比から決める**ようにした（`pageTextDistanceFactor`）。横長の画面では従来のままにする。
- 背表紙を見せる段は逆に、**本（幅 2.85）が近すぎて表紙が画面を覆っていた**ので、向きを変えずに距離だけ、背表紙が入るところまで下げた（`spineCameraDistance`、霧に沈まない 4.2 が上限）。あわせて、この段だけ主光源の輪を広げた（背表紙が既定の輪の外にあり、強さを足しても届かなかった）。

## 引き継ぎ事項・注意点

### 演出を触るときは、必ず描画させて見ること

**今回の4件は、コードを読んだだけでは「実装済み」に見えていた。** 管理表の改善方法にも「非均一スケールを適用し」「背表紙を強化し」と書いてあり、実際にその名前の処理も入っていた。**入っていたが、軸が逆で、装飾は箱の中に埋まっていた。** 見た目の課題は、見ないと分からない。

**この環境で見る手順**（`pnpm dev` を起動しておく）:

- Playwright は導入済み。Chromium は `/opt/pw-browsers/chromium` にあり、`--use-gl=swiftshader --enable-unsafe-swiftshader` で WebGL が動く。
- **`newPage` に `reducedMotion: "no-preference"` を渡す。** 既定だと `prefers-reduced-motion: reduce` が立ち、3D版でも演出が150msで終わる。
- **スクリーンショット1枚に実時間で3〜7秒かかる。** 7.4秒の演出は撮っている間に終わるので、**`TIMELINE` を一時的に8〜40倍へ延ばしてから撮る。**
- Playwright の `page.clock` は使えるが、**`runFor` で進めた時間よりアプリ側の経過時間が進む**（描画の実時間が漏れる）。段を狙って撮るなら、時刻ではなく**いまの段を読んで待つ**ほうが確実。
- 段を読むには、`archive-scene.tsx` の `useFrame` の中で `window` へ phase を書き出す行を一時的に足す。**戻し忘れに注意**（`git diff` で確認する）。

### 新しく分かった実装の事実

- **drei の `Html` は `transform` のとき、要素の世界での大きさが `px * distanceFactor / 400` で決まる。** 親の `scale` もそのまま掛かる。棚姿勢では親のスケールが軸ごとに違うが、背表紙の幅（0.36）と高さ（0.368）はほぼ同じなので、ラベルは潰れない。
- 背表紙のラベルから `occlude` を外した。題箋の上に載るだけで間に入るものがなく、遮蔽の判定は毎フレームの ray を1本増やすだけだった。
- `spotLight` は `angle` の外側には届かない。**強さを足しても、輪の外にあるものは明るくならない。**
- **`three` は `PCFSoftShadowMap` を非推奨にしており、指定しても `PCFShadowMap` になる**（ブラウザのコンソールに警告が出る）。`quality.ts` の `softShadows` は現在のところ見た目に効いていない。今回は触っていない。
