## 引き継ぎ事項・注意点

### 今回の修正について

- **節目のねぎらいは「値が今日動いたか」で判定する。** 記録日数の累計は新しい記録がなければ動かないので、節目ちょうどの値かどうかだけでは「今日届いた」と言えない。判定を変えるときは `milestones.test.ts` の「記録した日の節目は、その累計に届いた日を過ぎたら祝わない」が効く。**数日前の日付をあとから記録して節目に届いた場合はねぎらいを出さない**仕様にしてある（届いたのはその記録の日付の話であり、今日ではないため）。チェックリスト F-10「翌日には出ない」はこの修正で満たされる。
- **暦日の妥当性を確認しているのは復職日だけ。** `dailyRecordSchema.date` は書式の正規表現のままにした。ここを厳しくすると読み取り時に記録の配列全体が `CORRUPTED` になり、記録一覧そのものが開けなくなる。影響範囲が指摘の内容に対して大きすぎると判断した。塞ぐ場合は、読み取り経路ではなく取り込み境界だけに適用すること。
- サインを選び直したときにタグと補足を消す変更は、**この修正より前に保存された記録には遡って効かない。** 隠れたタグを持つ記録が端末に残っている可能性があるため、`SelfCareSuggestionCard` へ渡す側でも `showWarningTags` で絞っている。**表示側の絞り込みを外すと既存データで問題が再発する。**
- **自動レビューはPRごとに走るが、指摘は自動では解決されない。** マージ前に `get_review_comments` で確認し、直すか直さないかをその場で決めること（手順7に明文化した）。

### 積み重ね表示について

- **復職日は外部へ渡る型に入れていない。** `DailyView` と `PeriodSummary` はどちらも変更していない。選択式ではあるが、休職と復職という職歴上の事実を1つの日付で示すため。`docs/ai-consent-decision.md` の1節・3節にこの判断を書いた。LLM呼び出しを実装するときは3節の表を前提にすること。
- 取り込み（`importBackup`）は、復職日を持たない書き出しを読むと端末の復職日を未設定へ戻す。端末に残った前の設定が、取り込んだ記録の起点として残らないようにするため。
- 起点が何年も前だと `enumerateDates` の上限（`MAX_RANGE_DAYS` = 3700）を超えるため、`streakWindowStart` で記録がある最古の日まで窓を縮めている。連続は記録がある日にしか生まれないので結果は変わらない。
- 経過日数は起点当日を0として数える。節目の7日は「起点の7日後」であり「7日目」ではない。月は暦月ではなく30日で数える。
- 表示の文言を足すときは禁止語のテストが効く。一覧は `src/lib/self-care.test.ts`、`src/lib/ai/milestones.test.ts`、`src/components/reflection/accumulation-card.test.tsx`。「この調子で」「続けましょう」は助言なので出さない。
- 実機テストで「週のまとめのほうを先に見たい」という所見が出た場合、積み重ねと週のまとめの順序入れ替えは `reflection-tab.tsx` の1箇所で済む。
