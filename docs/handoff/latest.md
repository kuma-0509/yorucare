## 引き継ぎ事項・注意点

- **節目のねぎらいは「値が今日動いたか」で判定する。** 記録日数の累計は新しい記録がなければ動かないので、節目ちょうどの値かどうかだけでは「今日届いた」と言えない。この判定を変えるときは `milestones.test.ts` の「記録した日の節目は、その累計に届いた日を過ぎたら祝わない」が効く。数日前の日付をあとから記録して節目に届いた場合はねぎらいを出さない仕様にしてある（届いたのはその記録の日付の話であり、今日ではないため）。
- **暦日の妥当性を確認しているのは復職日だけ。** `dailyRecordSchema.date` は書式の正規表現のままにした。ここを厳しくすると、読み取り時に記録の配列全体が `CORRUPTED` になり、記録一覧そのものが開けなくなる。影響範囲が指摘の内容に対して大きすぎると判断した。記録の日付はアプリが `toDateString` で生成するため実在しない日にはならないが、手で編集したバックアップを取り込む経路は残っている。ここを塞ぐ場合は、読み取り経路ではなく取り込み境界だけに適用すること。
- **復職日は外部へ渡る型に入れていない。** `DailyView` と `PeriodSummary` はどちらも変更していない。選択式ではあるが、休職と復職という職歴上の事実を1つの日付で示すため。`docs/ai-consent-decision.md` の1節・3節にこの判断を書いた。LLM呼び出しを実装するときは3節の表を前提にすること。
- 取り込み（`importBackup`）は、復職日を持たない書き出しを読むと端末の復職日を未設定へ戻す。取り込んだ記録に対して、端末に残った前の設定が起点として残らないようにするため。
- サインを選び直したときにタグと補足を消す変更（指摘3）は、**この修正より前に保存された記録には遡って効かない。** 隠れたタグを持つ記録が端末に残っている可能性があるため、`SelfCareSuggestionCard` へ渡す側でも `showWarningTags` で絞っている。表示側の絞り込みを外すと既存データで問題が再発する。
- 起点が何年も前だと `enumerateDates` の上限（`MAX_RANGE_DAYS` = 3700）を超えるため、`streakWindowStart` で記録がある最古の日まで窓を縮めている。連続は記録がある日にしか生まれないので結果は変わらない。
- 経過日数は起点当日を0として数える。節目の7日は「起点の7日後」であり「7日目」ではない。月は暦月ではなく30日で数える。
- 表示の文言を足すときは、禁止語のテストが効く。一覧は `src/lib/self-care.test.ts`、`src/lib/ai/milestones.test.ts`、`src/components/reflection/accumulation-card.test.tsx` にある。「この調子で」「続けましょう」は助言なので出さない。
- 4件目からの持ち越しで、未確認の論点が1件そのまま残っている。管理表の「本棚演出の方向性確定前には着手しない項目がある」（判断済み）にある「本番データ構造の `DailyRecord` と `schemas.ts` は変更しない」を、記録完了演出の作業に対する制約と解釈して2件目・4件目が `DailyRecord` を、5件目が `schemas.ts` を変更した。**演出側の作業を再開する前に、この解釈で問題がないか確認してほしい。**
