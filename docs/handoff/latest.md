## 引き継ぎ事項・注意点

- **持ち越しの未確認論点は解消した。** 管理表「本棚演出の方向性確定前には着手しない項目がある」の「本番データ構造の `DailyRecord` と `schemas.ts` は変更しない」は、**記録完了演出の作業に対する制約**であり、記録・ふりかえり本体の機能実装を縛らない、とユーザー確認のうえ確定して管理表の同じ行に追記した（2026-08-15 確認）。2件目・4件目の `DailyRecord` 変更、5件目の `schemas.ts` 変更は、この解釈で問題ない。**演出側の作業を再開するときは、`DailyRecord` と `schemas.ts` を変更しないこと。**
- **コードは一切変更していない。** 今回は文書のみ。`STORAGE_SCHEMA_VERSION`（3）、`EXPORT_VERSION`（1）、`DailyRecord`、`ExportPayload`、`DailyView`、`PeriodSummary` はいずれも据え置き。`docs/ai-consent-decision.md` も、渡す項目が増えていないため見直しの対象にならなかった。
- **チェックリストのK章は「入力内容を書かない」ことを前提に作ってある。** 実施結果に、メモ本文、目標の文面、選んだ気持ち、しんどさの自由記述、感想を書かないこと。書くのは操作と起きたことだけ。タスクテストの集計も人数だけを書く欄にしてある。これは管理表と同じ制約（`AGENTS.md` の開発管理）をチェックリスト側にも降ろしたもの。
- **C-10（前日の目標のふりかえり）は仕込みが要る。** 日付を昨日に切り替えて目標を保存してから今日に戻さないとカードが出ない。推奨テスト順の6番にその手順を書いてある。テスト時にここを飛ばすと、P1で追加した機能の1つが未検証のまま終わる。
- **F章は積み重ね → 週のまとめ → グラフの順に並べてある。** 画面の並び順（`reflection-tab.tsx`）に合わせたため、項目IDは F-5 以降 → F-1〜F-4 という順で出てくる。IDが飛んで見えるのは既存IDを潰さないための意図。
- チェックリストの項目IDは、実機テストの結果を書くときの参照キーになる。**既存IDの意味を変えないこと。** 今回 D-7 だけは記述が実装と食い違っていたため中身を差し替えた（範囲外の項目だったので、過去の実施結果と衝突しない）。
- 実機テストで「週のまとめのほうを先に見たい」という所見が出た場合、積み重ねと週のまとめの順序入れ替えは `reflection-tab.tsx` の1箇所で済む（5件目からの持ち越し情報）。
- 公開URL（https://yorucare.vercel.app）に今回のP1機能が反映されているかは未確認。実機テストの前に、フッターの更新日付（A-8）で最新版かどうかを必ず見ること。古い版を触ると、追加した確認項目がすべてNGになる。
