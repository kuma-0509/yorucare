**数値はアプリが埋め、文章の穴だけをLLMが書く穴埋め方式**で、期間の報告書を組み立てられるようにした。実装したのは (1) 報告書の骨格（数値を確定させる層）、(2) LLMが書いた文を検証する層、(3) 穴を埋める境界と差し替え、(4) プレーンテキスト出力、(5) 確認用のプレビュー画面の5つ。**外部AI APIへ送る実装は入れていない**（`docs/phase2-plan.md` 5節・`docs/sharing-decision.md` 12節）。**演出（`completion` 配下）には一切手を出していない。** `DailyRecord` と `schemas.ts` も変更していない。

### 先に決めた3点（依頼で「先に決めて引き継ぎに残す」とされていた分）

#### 1. 本番投入の扱い → **既定で無効 かつ 本番画面から到達不可**（両方）

- `isExternalNarrativeEnabled()` は **常に false を返す関数として固定**した。**環境変数では切り替えられない。** 設定ミスで本番から送信が始まる経路を作らないため。
- `resolveNarrativeFiller()` は常に `null` を返す。**外部へ送る `NarrativeFiller` はリポジトリに同梱していない。** 実装したのは差し替え可能な1つの関数型と、その戻り値の検証まで。
- 画面は `/preview/report` にだけ置いた。`src/app/preview/layout.tsx` が本番ビルドで `notFound()` を返すので、**本番では 404 になる**。ふりかえりタブなど本番の導線には出していない。

#### 2. 表現の制約 → **「出力を検証する層を通す」を採用**（「穴の選択肢を定型に限る」は採らない）

- 定型の選択肢だけにすると、LLMの仕事が並べ替えだけになり、週次まとめと同じ定型ルールで足りてしまう。一方で検証層は、モデルやプロンプトを差し替えてもそのまま効く。**プロンプトは守られる保証がないが、検証は保証になる。**
- `verifyNarrative` が弾くもの: 空／文字数超過／改行・制御文字／**数を含む文**／評価語・助言・診断・危機に読める語／URLらしき文字列。
- **数を弾くのは意図的。** 数値はアプリが埋めると決めたので、LLMの文に数が出ること自体を方針違反として扱う。漢数字（一〜億）や「割」「%」まで弾くため「一日ずつ」のような自然な言い回しも落ちるが、**落ちた穴は定型文になるだけ**で、報告書の数値が壊れるより安全側になる。
- 禁止語は既存の4ファイル（`self-care.test.ts` / `milestones.test.ts` / `accumulation-card.test.tsx` / `completion-choice.test.tsx`）で固定していた語を `NARRATIVE_FORBIDDEN_WORDS` に1か所へまとめた。**「しましょう」ではなく「ましょう」で持っている**（「寝ましょう」を拾えなかったため。テストで確認済み）。
- 検証は**節ごとに独立**。1つ落ちても他の節のLLM文は残る。filler が例外を投げた場合と、戻り値が配列でない場合も、すべて定型文で報告書が成立する。

#### 3. 報告書に載せる項目 → **`docs/sharing-decision.md` 5節の初期版に合わせる**

載せるのは **対象期間・記録した日数・状態の推移・睡眠時間の推移・できたことがあった日数だけ**。服薬、しんどさのサイン、タグ、メモ、できることの名前、カスタム状態ラベルは載せない。**就寝時刻も載せない**（同節が「時刻ではなく時間量の推移だけ」としているため）。数値が無い節は節ごと省き、0を並べて不足として読ませない。

### 型で保証したこと（依頼で「境界を越えやすい」と指摘されていた分）

- `ReportSkeleton` / `ReportSection` / `ReportFact` に本文のフィールドを置いていない。復職日も持たせていない。
- **LLMへ渡すのは骨格だけ。** `buildNarrativeRequest` は `ReportSkeleton` の見出しと数値だけを写す。生の記録、`PeriodSummary` の未使用項目、`DailyView`、辞書のタイトルは渡らない。**LLMは報告書に出ている以上のことを知らないので、載せないと決めた項目について書きようがない。**
- 3節の表の「日付そのものは期間の端だけ」に合わせ、**日単位の `DailyView` も報告書の経路では渡さない**（報告書は期間集計から作るので必要がない）。
- 書き込み系のツールは増やしていない。`tools.ts` に足したのは読み取りの `getReportSkeleton` だけ。

## 引き継ぎ事項・注意点

### なぜ `完了` ではなく `保留` にしたか

実装できる範囲（骨格・検証層・境界・テキスト出力・プレビュー）は入れ終わったが、**LLMを実際に呼ぶ経路そのものは入れていない**。外部送信は Gate 3 と別途のデータ取扱い判断まで行わないと文書で決まっているため、「実装しなかった」ではなく「条件待ちで着手しない」が実態に合う。管理表の `保留` は 14行目・16行目（Gate待ちの行）と同じ使い方をしている。**次のチャットがこの行を見て「まだ何も無い」と読まないよう、改善方法に実装済みの範囲を書いてある。**

### 今回の変更で前提が変わったこと

- **禁止語の一覧が `src/lib/ai/narrative-guard.ts` にもできた。** 既存の4つのテストにある一覧は**そのまま残してある**（画面ごとに出してよい語が違うため。例えば報告書の注意書きは「診断や治療の判断には使えません」なので、`report-card.test.tsx` の禁止語一覧からは診断・治療・医師を外している）。**表示の文言を足すときは、まず該当画面のテストの一覧を見ること。**
- **`COPY.report` を追加した。** 報告書に出る文言はすべてここにある。定型のフォールバック文も画面に出るので `COPY` から取っている。**フォールバック文は `verifyNarrative` を通ることをテストで固定してある**ので、書き換えるときは数字・評価語・助言を入れない。
- **`buildReportSkeleton` は数値を自前で計算しない。** `summarizePeriod` の戻り値を並べ替えて言い方を決めるだけ。例外は `countSelfCareDoneDays`（「できることを1つ以上実行した日数」は既存の集計に無かった）で、これも辞書から消えた項目を数えない点を `listSelfCare` と揃えてある。
- **対象期間は1週間固定**（`REPORT_DAYS = 7`、`docs/sharing-decision.md` 5節「1週間を明示する」）。`buildReportSkeleton` 自体は任意の期間を受け取れるので、変えるなら画面側で決める。
- **`/preview` の入口に「期間の報告書を見る」が増えた。** 見出しは「演出プロトタイプ」のままなので、次に触るときに整えてもよい。
