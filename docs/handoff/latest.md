# Handoff

日付: 2026-08-17
担当チャット: 7件目

## 今回のきっかけ

2026年7月に受け取ったヨルケアアプリのアンケート回答（利用者1名・自由記述）を、現行実装と1件ずつ突き合わせた。反映済み・未反映を判定し、未反映のものを優先して実装した。

**アンケート原本は取り込んでいない。** 回答は利用者の入力内容そのものであり、`AGENTS.md` の開発管理の制約に従って、管理表にも本リポジトリにも原文を残していない。管理表と本メモに書いたのは、一般化した課題と改善方法だけ。

## 実装したもの

### 1. 控えたいこと（`kind` と `stateLevels`）

- `SelfCareItem` に `kind`（`care` / `avoid`）と `stateLevels`（空配列＝いつでも）を追加。`STORAGE_SCHEMA_VERSION` を 3 → **4**。既定値つきのため版3以前の保存データはそのまま読め、既存の登録は「できること」「いつでも」になる。`EXPORT_VERSION` は 1 のまま。
- **どの状態の日に出すかは本人が登録時に指定する。** 記録の中身から推定していない。`src/lib/self-care-list.ts` がやるのは、本人の指定とその日の状態を突き合わせることだけ。
- **控えたいことは実施の可否を記録しない。** 守れなかった日を失敗として残さないため、カードに押せる要素を置いていない（表示テストで固定）。`DailyRecord` は変更していない。
- 「今日できたこと」の候補も状態で絞るようにしたが、**すでにその日に選んである項目は必ず残す**（`selectCareItemsForRecord`）。状態を選び直したときに、選択済みの項目が画面から消えたまま保存されるのを防ぐため。
- AI層の2箇所から控えたいことを外した。`getSelfCareDictionary`（提案の候補に入れないため）と `relateSelfCareToMood`（実行日が必ず0日になり「一度もできなかったこと」として並ぶため）。

### 2. グラフの重ね表示

- 主の項目に加えて比べる項目を1つ選べるようにした（`CompareMetricTabs`）。主の項目自身は選択肢に出さず、主を切り替えて重複したら重ね表示を自動で外す。
- 単位が違うため**右側に別の目盛り**を置いた。線は色に加えて**破線**でも区別でき、凡例にどちらの目盛りで読むかを書いている。
- **相関の強さや向きは算出していない。** 目盛りを並べるだけにとどめ、「同じ時期に動いて見えても、どちらかがもう一方の原因であるとは限りません。」を画面に出す。重ねた側にも母数の日数を添えた。

### 3. お薬メモと、お薬の書類（PDF）

- 日々の記録とは別に1つだけ持つ（`STORAGE_KEYS.medicationNote`）。全タブ共通ヘッダーの「相談先」の隣から、本人が開いたときだけ表示する。
- **端末の外へ出す手段を持たせていない。** 集計にもグラフにも使わず、生成AI共有の項目にも入れない。共有文の組み立て（`ai-share-text.ts`）は記録と登録簿だけを受け取るため、**型の上でも渡らない**。`docs/ai-consent-decision.md` の表に「渡さない」として追記済み。
- 書き出しには含め、取り込みでファイルの内容へ置き換える（お薬メモを持たない古いファイルからの取り込みでは未入力へ戻る）。復職日と同じ扱い。
- 取り扱いの注意と、お薬のことは主治医・薬剤師へ相談する旨を画面に添えた。

同じ画面に**お薬の書類（PDF）**を足した。処方の控えやお薬手帳の写しを端末内に置き、必要なときに本人の操作だけで開ける。

- **2枚目以降は、保存の前に「新しく追加する」か「既存のどれと差し替えるか」を必ず選ばせる。** 黙って上書きしない。差し替えでは、いつから持っている書類かを見失わないよう `addedAt` を引き継ぎ、`updatedAt` だけを新しくする。
- **保存先は IndexedDB。** localStorage は目安5MBを記録・できること・お薬メモと分け合っており、書類を入れると1件で容量を使い切って記録の保存が止まりうる。
- **中身は Blob ではなく ArrayBuffer で持つ。** IndexedDB へ Blob を入れる実装は環境差があり、iOS Safari で取り出せなくなる不具合が知られている。読み出すときに Blob へ組み直す。テスト環境（jsdom + fake-indexeddb）でも Blob は構造化複製できず、この設計に変えて初めて中身の読み書きをテストできるようになった。
- 受け入れの判定は拡張子と MIME 型の自己申告だけに頼らず、**先頭バイトが `%PDF` で始まること**を確かめる。上限は1件5MB・20件。
- **書き出しファイルには含めない。** 氏名・生年月日・医療機関名が入りうるため、持ち運べるファイルへ載せない。画面にもその旨を出している。共有端末の全削除（`records-tab.tsx`）では書類も一緒に消す。
- 開くときは、その場で作った参照から本人が開くだけ。参照は60秒後に破棄する。

### 4. 気持ちとしんどさのサインの役割分け（ユーザーが案Aを選択）

重なりはサインの「気分・感情」5語だけに集中していた（不安↔強い不安、イライラ↔イライラが強い など）。

- **サインを「体と生活に出た変化」だけに絞った。** 区分は 睡眠・生活リズム／**からだ**／仕事・外出／その他 に変えた。`WARNING_TAGS_MOOD` は廃止し、体の変化である「涙が出る」は `WARNING_TAGS_BODY` へ移した。
- **外した語に対応する気持ちのラベルを補った**（「落ち込み」「焦り」を追加）。選択肢が消えただけで、記録できる内容が減らないようにするため。
- 程度は3段階の状態とサインの3段階（なし／少しあり／あり）で表す。程度つきの言い換え語（「強い不安」）はもう置かない。
- **両方に同じ語や言い換えを置かないことを `warning-tags.test.ts` で固定した。** 語を足すときに、また重なりが戻るのを防ぐため。
- **過去の記録は壊れない。** `warningTags` は文字列配列なので、選択肢から外した語も保存済みの記録にはそのまま残り、一覧と週のまとめでこれまでどおり読める。移行処理は要らない。
- 自分メンテの案は、感情タグ由来だった2案（ゆっくり3回、息を吐く／今の気持ちを1行だけ書く）を `WARNING_TAGS_BODY` に付け替えた。案が消えないようにするため。

### 5. 「できること」グラフの説明（ユーザーが案Aを選択）

- 説明文を「その日にできた『できること』の数」から、「…の数です。気分や睡眠と重ねると、増えた時期・減った時期を見比べられます」へ変えた。何を見る線かを書き、件数の多さだけを目安に読ませない。
- グラフからは外していない。今回の重ね表示で、相方としての使い道ができたため。実行日と非実行日の差分（`self-care-relation.ts` に実装済み・未表示）を出すかは、実機の所見を見てから判断する。

## 引き継ぎ事項・注意点

- **`STORAGE_SCHEMA_VERSION` を 4 に上げた。** 移行は登録簿の書き戻しだけで、記録側は変更していない。版3の保存データからの移行は `repository.test.ts` の「控えたいこと追加後の登録簿の移行」で固定してある。
- **`DailyRecord` と `EXPORT_VERSION` は据え置き。** 控えたいことは実施を記録しないため、記録側に足すものがなかった。演出側の作業を再開するときの制約（`DailyRecord` と `schemas.ts` を変更しない）は、演出の作業に対するものという前回の確定どおり。
- **控えたいことに「守れた／守れなかった」を後から足さないこと。** 足すと、できなかった日を失敗として残す設計になり、`docs/phase2-plan.md` の「未入力や中断を失敗として扱わない」と衝突する。`avoid-list-card.test.tsx` が押せる要素の不在を固定している。
- **重ねたグラフに相関係数や「◯◯すると△△が上がる」に読める表示を足さないこと。** `docs/ai-consent-decision.md` と `self-care-relation.ts` が一貫して避けてきた方向であり、グラフ側だけ緩めると全体の整合が崩れる。
- **お薬メモとお薬の書類を、共有・送信の経路に載せないこと。** 現在は型の上で渡らない状態を保っている（`buildAiShareText` が記録と登録簿しか受け取らない）。共有の入力を増やす変更をするときは、この保証が残っているかを必ず確認する。
- **お薬の書類を書き出しファイルへ含めないこと。** 含めると、氏名や医療機関名が入りうるファイルが端末の外へ持ち出せるようになる。機種変更で書類が引き継げないのは承知のうえの判断で、元のPDFは本人が保管する前提を画面に書いてある。方針を変えるなら、`docs/sharing-decision.md` と `docs/ai-consent-decision.md` の両方を先に見直すこと。
- **書類の保存を IndexedDB から localStorage へ戻さないこと。** 記録の保存が容量不足で止まる。また中身を Blob で持たせ直さないこと。iOS Safari で取り出せなくなる。
- **しんどさのサインへ感情の語を戻さないこと。** `warning-tags.test.ts` が重なりを禁じている。語を足したくなったら、それが「感じている気持ち」なのか「体と生活に出た変化」なのかを先に決め、前者なら気持ちのラベルへ足す。
- アンケートは1名分の回答であり、母数が小さい。今回の機能は「要望があったから作った」ものであって、需要が確認されたわけではない。実機テストと Gate 1 の観測で、実際に使われるかを見てから広げること。
