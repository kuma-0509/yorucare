# 相談窓口導線の設計

最終確認日: 2026-08-06
状態: 完了（2026-08-06 に都道府県内の支援先検索を追加）

## 1. 目的

利用者がどのタブを開いていても、スマートフォンから少ない操作で公的な相談先へ到達できるようにする。

この導線は、ヨルケアによる診断、治療、処方、危機判定、24時間監視、相談員による対応を提供するものではない。

## 2. 常設する導線

- 全タブ共通のヘッダー右上に `相談先` ボタンを表示する
- ボタンを押すと、画面内のダイアログで相談先を目的別に表示する
- 記録前、記録後のコンパクト表示、記録一覧、セルフケア、ふりかえりのすべてから同じ操作で開けるようにする
- 44px以上の操作領域を確保し、キーボード操作と読み上げに対応する

## 3. 表示順

1. 命や身体に差し迫った危険: 救急・消防の119、事件・事故の110
2. つらい気持ちを今すぐ話したい: 厚生労働省掲載の `#いのちSOS` と `まもろうよ こころ`
3. 仕事や復職の悩み: 厚生労働省 `こころの耳` の相談窓口
4. 診断、治療、薬の相談: 主治医または医療機関へ相談する案内

緊急通報と一般相談を混同させず、利用者自身が状況に近いものを選ぶ。アプリは入力内容から危険度を推定しない。

## 4. データ境界

- ダイアログを開いても端末内の記録を読み取らない
- 記録本文、選択値、端末IDを相談窓口へ送信しない
- 相談先の表示やクリックを匿名利用イベントとして送信しない
- 電話発信と外部サイトの表示は、本人がボタンを選んだ場合だけ端末へ依頼する
- 外部サイトへ移動した後は、その提供者の利用規約と個人情報の取扱いが適用される

## 5. 受付条件の扱い

電話番号と受付条件は変更される可能性がある。公開前と定期確認時に公式ページで見直す。画面上でも最新の受付状況を公式ページで確認するよう案内する。

## 6. 受入確認

- 全タブの上部に `相談先` が常設されている
- スマートフォン幅でボタン、見出し、電話番号が折り重ならない
- ダイアログ内が縦にスクロールでき、下端の説明まで読める
- 119、110、#いのちSOSが正しい `tel:` URLを持つ
- 外部リンクが厚生労働省のHTTPSページに限定されている
- ダイアログを閉じると元の入力状態へ戻れる
- ブラウザコンソールにエラーがない

## 7. 都道府県内の支援先検索（2026-08-06 追加）

### 7.1 位置づけ

第3章の表示順1〜2位（119・110、`#いのちSOS` と `まもろうよ こころ`）はそのまま維持し、その下に条件で絞り込める一覧を置く。新しいタブは作らず、ヘッダー常設の同じダイアログ内で完結させる。

安全に関する案内（ひとりにならない、119・110、公的窓口、安全な場所へ移動）は、入力内容をきっかけに表示するのではなく、ダイアログ最上部に常設する。

### 7.2 本人が選ぶ条件

市区町村、相談内容（こころの健康／医療機関／就労・生活／発達障害／福祉窓口）、相談方法（電話／オンライン／対面）、いつ相談したいか（今すぐ／今日中／数日以内）。

「いつ相談したいか」は本人の選択であり、アプリが記録から推定した値を渡さない。この条件は並び順だけを変え、絞り込みには使わない。絞り込みに使うと、受付時間外の時間帯に候補が0件になり、選べる先がない画面になるため。

### 7.3 現在時刻と曜日から出すもの

受付中／本日は受付終了／本日この後に受付／次回受付日時／24時間対応／予約要否／相談方法。受付時刻が日をまたぐ窓口は、前日の受付が続いているかも見る。受付条件がデータにない場合は「確認が必要」とし、受付中として扱わない。

### 7.4 並び順

1. 本人が選んだ緊急度との適合
2. 現在受付中か
3. 市区町村の適合（都全域が対象の窓口は、市区町村を選んでいても候補に残す）
4. 相談内容の適合

同順位は id 昇順で固定する。同じ操作で並びが変わると、前回見た窓口を探せなくなるため。

### 7.5 データ境界

支援先データは `src/lib/support/` に置き、本人の記録を扱う `src/lib/repository.ts` 配下を参照しない。この境界はテスト（`module-boundary.test.ts`）で固定する。参照できてしまうと「記録の内容に応じて表示する窓口を変える」実装が書けるため、経路そのものを塞ぐ。

第4章のデータ境界（記録を読み取らない・送信しない・表示やクリックを利用イベントにしない）は、この検索にもそのまま適用する。

### 7.6 出典とデモデータ

すべての外部データに `DataSource`（提供者／データセット名／更新日／参照URL／デモか実データか／**利用の根拠**）を持たせ、ダイアログ内に「データについて」を設ける。更新日が確認できない場合は、利用前に公式サイトか電話で確認するよう案内する。ライセンス表記が必要な場合も同じ場所に出す。

実データは、掲載元のライセンスか個別の許諾が確認できたものだけを表示する。根拠が未確認のデータは、アダプターが読み込み自体を拒否する。詳細と確認手順は `docs/open-data-licensing.md` に置く。

実URLとデータ形式、および利用条件が確認できていないため、MVPはローカルJSONのデモデータで動かす。デモデータは電話番号とURLを持たず（アダプターの読み込み時に検査する）、画面上で「デモデータ」と明示する。
