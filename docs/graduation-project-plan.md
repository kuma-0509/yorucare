## 1. お題（卒業制作で作るもの）

**ヨルケア** — 精神障害と向き合いながら働いている人が、1日1〜2分で自分の状態を残し、それを**渡せる事実**に変えるセルフケア記録アプリ。

卒業制作としての完成形は「アプリが動くこと」ではない。**あいまいな記憶で行われている復職後のやりとりを、客観的な記録・週次の要約・月1回の数値に置き換える**こと。その材料を本人が選んで渡せるところまでを完成形とする。

アプリ本体は Phase 1 MVP が稼働済み（https://yorucare.vercel.app ）。卒業制作期間で作るのは、記録の先にある「数値化」「要約」「渡す」の部分と、続けられる入力設計である。

---

## 2. 解決したい課題

### 2.1 全体フローの中での位置

復職までの流れは次のようになっている。

| 段階 | 内容 | 関わる人 |
|---|---|---|
| 医療 | うつ症状 → 治療 | 主治医・医療機関 |
| リワーク | 復職の準備 | 支援機関・プログラム |
| **企業（自分の持ち場）** | **職場復帰 → 就労継続のサポート** | **職場内サポーター・産業医・支援者** |

治療とリワークには、症状や課題を見るための共通のものさしがある。**職場復帰したあとには、それがない。**

### 2.2 課題の中心：判断材料があいまいな記憶しかない

復職後のサポートで判断材料になっているのは、次の2つだけである。

| 判断材料 | 実態 |
|---|---|
| 本人の自覚 | 「なんとなくしんどい」「たぶん先週よりはマシ」。しんどい時期ほど、いつから崩れたのかを思い出せない |
| 周囲が見た様子 | 「最近つらそうに見える」「顔色が良くなった」。見えている場面はごく一部で、夜と休日は含まれない |

> このあいまいな記憶を材料に、本人はサポートを求め、周囲は判断している。

これは本人の努力不足でも、周囲の配慮不足でもない。**伝えるべき事実が、伝わる形で残っていない**という構造の問題であり、コミュニケーションロスである。

なお、支援そのものが**平日・日中**を前提に組まれており、心身が乱れやすい**平日夜間と土日祝**に機能する支援がほぼないという構造も、この空白を広げている。

### 2.3 ヒアリングで確認した事実

`docs/evidence/vha2026-entry-summary.md` より、一般化して発表に使える事実。

| 出典 | 内容 |
|---|---|
| 当事者A | 夜間のSNS閲覧が常態化し、睡眠不足・不調を招く |
| 当事者B | 会社には相談しにくい。支援面談は月1回。自作Excelで孤独に体調管理 |
| 支援員 | 復職後1〜2ヶ月で体調管理記録が途切れる。面談は仕事ができているかの確認で精一杯で、生活面・体調まで踏み込む時間がない |

記録が続かないことが問題の中心ではない。**続かない記録は、相談の材料にならない**ことが問題である。

## 3. なぜ作りたいのか

3つある。発表では1つ目と3つ目を主に話す。

1. **復職後だけ、共通のものさしがない。** 治療にもリワークにも指標があるのに、職場に戻ったあとは記憶で会話するしかない。就労継続をサポートする立場として、毎回ここで困っている。
2. **既存アプリでは足りない。** 服薬管理に特化したものが多く、体調の波・生活リズム・その日できたことを一体で扱えるものが不足している。自作Excelに逃げる人がいるのはそのためで、Excelは相談の場に持ち出しにくい。
3. **記録アプリは「責める道具」になりやすい。** 連続記録を強調するアプリは、書けない日が続いた人ほど戻ってこられなくする。書けなかった時期を失敗として表示しない設計を、自分で決めて自分で作りたい。

## 4. 何を作るのか

### 4.0 あいまいな記憶を、渡せる事実に変える3つ

| 頻度 | 機能 | 内容 |
|---|---|---|
| 毎日1〜2分 | 客観視できる記録 | 気分・睡眠・お薬・しんどさのサイン・できたこと・メモ |
| 週ごと | まとめて要約し、伝える | 1週間分を、本人が選んで渡せる短い文章にする |
| 月1回 | K6で数値化 | 国の調査で使われている6つの質問。0〜24点と、前回からの変化 |

得られる結果は2方向ある。

- **自分に対して**: 自分の状態を俯瞰して見られるようになり、セルフケアの判断に使える
- **相手に対して**: 医療従事者・支援者・職場内サポーターへ端的にすぐ伝えられ、**受けるサポートが最適化される**

### 4.1 いま動いているもの（Phase 1 MVP）

- 4タブ構成: 書く／これまで／できること／ふりかえり
- 記録項目: 気分・睡眠・お薬・しんどさのサイン・できたこと・メモ（1日1〜2分）
- 「できること」辞書の CRUD（自分用のセルフケア選択肢を育てる）
- ふりかえりの期間別グラフと、直近7日の週次まとめ
- 記録のファイル保存・復元、保存忘れの能動的リマインド
- 全タブ共通の相談窓口導線（緊急通報・公的窓口・仕事の相談・医療相談を区別）
- 任意同意の匿名利用イベント計測（記録本文は送らない）

### 4.2 卒業制作期間で作る山場

| 優先 | 作るもの | 完成の判断 |
|---|---|---|
| 1 | 3段階の入口で入力を削る（よい／ふつう／しんどい を選ぶと追加質問が絞られる） | ダミーデータで5人中4人以上が2分以内に保存できる |
| 2 | 月1回のK6記録と推移表示 | 毎回同じ6問・同じ選択肢で0〜24点を保存し、前回との差が見える。判定・勧奨は行わない |
| 3 | 週次まとめの言語化（数値はアプリが埋め、文章の穴だけをAIが書く穴埋め方式） | 数値・母数がアプリ側で確定し、AIが数値を書き換えられない |
| 4 | 本人が選んで渡せる相談材料の出力 | 全文を本人が確認してからでないと、端末外へ出せない |

すでに `src/lib/ai/` に期間集計・頻度集計・連続日数・セルフケア実行日との差分が実装済みで、数値を確定させる土台はできている。残っているのは、K6という定点のものさし、その数値を文章にする層、本人が確認して渡す導線である。

`docs/phase2-plan.md` の実装優先順位では、P1 の中で入力負担を下げる変更を最初に行うと決めている。この4項目もその順に並べ、1つ入れて観測してから次を決める。

### 4.3 K6の扱い（実装前に確定させる境界）

K6は、過去30日間の心理的な状態を6つの質問で尋ね、各0〜4点・合計0〜24点で表す尺度で、国民生活基礎調査などの国の調査で使われている。**同じ質問を毎月繰り返すため、本人と周囲が同じものさしで変化を見られる**点が、復職後の「あいまいな記憶」を置き換える手段になる。

アプリで**行うこと**:

- 月1回、同じ6問・同じ選択肢で回答を記録する
- 合計点と、前回・前々回との変化を並べて表示する
- 本人が選べば、週次の要約に合計点と変化を含める

アプリで**行わないこと**:

- カットオフ値による重症度の判定、状態の分類、ラベル付け
- 点数に基づく受診勧奨、危機判定、警告表示
- 点数の自動送信（他の記録と同じく、本人の明示操作でのみ端末外へ出す）

理由は、判定は医療の役割であり、アプリが肩代わりすると診断・治療の代替になるため。ヨルケアの既存方針（`AGENTS.md`／`docs/phase2-plan.md`）と同じ線を引く。なお、K6の数値はアプリの利用指標ではなく本人の記録であり、匿名利用イベントには含めない。

### 4.3 作らないと決めたもの

企画として明示的に外している。質疑で必ず聞かれるので、理由まで用意する。

| 作らないもの | 理由 |
|---|---|
| 記録本文の自動クラウド保存 | 現在の参加説明が「本人端末内・運営は閲覧しない」であり、変えるには同意と研究手続きの取り直しが要る |
| 勤務先・支援機関への自動共有 | 記録が評価材料になった時点で、本人が正直に書けなくなる |
| 通知によるリマインド | 継続率が低いことだけを理由に作らない。「忘れる」が非継続理由の30%以上を占めたときだけ作る |
| K6の点数による重症度判定・受診勧奨 | 数値化は本人と周囲が変化を見るためのもの。判定は医療の役割で、アプリが肩代わりしない |
| 症状の判定・助言 | 診断・治療の代替にしない。ガイドラインの推奨を製品の効能として主張しない |

## 5. 設計の芯（他の記録アプリと違うところ）

発表で最も伝えたい4点。

1. **記録は本人の端末にだけ残る。** 自動送信しない。運営も見られない。
2. **書けなかった日を失敗にしない。** 連続記録を強調せず、中断後に戻れることを指標に置く（中断後再開率）。
3. **数値と言葉の担当を分ける。** 集計はアプリが確定させ、AIは文章の穴だけを埋める。対象0件のときは0ではなく「データがない」を返し、「値が低い」と混同させない。
4. **アプリで抱え込ませない。** しんどさが強いときは、アプリの中で解決させず、相談窓口へ渡す導線を全タブに常設する。

## 6. どう良し悪しを判断するか

作って終わりにしないため、`docs/phase2-plan.md` で投資判断ゲートを先に決めてある。

| 指標 | 定義 | 判断したいこと |
|---|---|---|
| 初週複数日記録率 | Day 0〜6 に2日以上記録がある割合 | 初回だけで終わらないか |
| Week 2 継続率 | Day 7〜13 に1日以上記録がある割合 | 2週目に戻れるか |
| Week 4 継続率 | Day 21〜27 に1日以上記録がある割合 | 物珍しさを越えるか |
| 中断後再開率 | 7日以上空いた後に再度記録がある割合 | 中断を失敗にしない設計が効いているか |

これらはアプリの使いやすさを判断する指標であり、症状改善を示す指標ではない。医学的な評価は5か月間の実践研究（PHQ-9 等）と分けて扱う。

## 7. 想定質問と答え（質疑3分用）

| 質問 | 答え |
|---|---|
| その課題に誰がどれくらい困っているか | 復職後1〜2ヶ月で記録が途切れると支援員が証言。月1回の面談では間に合わない。まず21名の実践研究で確かめる |
| どんな場面で使うか | 平日の就寝前、または休日の夜。1日1〜2分。書けない日は飛ばしてよい |
| 既存の記録アプリではだめなのか | 服薬特化が多く、体調の波・生活リズム・できたことを一体で扱えない。自作Excelは相談の場に持ち出しにくい |
| なぜK6なのか | 国の調査で使われており、6問と短く、毎月同じ質問を繰り返せる。共通のものさしがない復職後に、定点の数値を置けるのが理由 |
| K6の点数で「危ない」と判定するのか | しない。カットオフ判定も受診勧奨も行わない。前回との変化を、本人と周囲が同じ数字で見るためのもの |
| 月1回で足りるのか | 日々の波は毎日の記録で見る。K6は月ごとの位置を確かめる定点。役割が違うので両方置く |
| AIは何をするのか | 集計はしない。アプリが確定させた数値を文章にするだけ。数値を書き換えさせない |
| メモ本文をAIに渡すのか | 渡さない。渡すのは集計値・選択式タグ・辞書のタイトルだけで、これは運用ルールではなく戻り値の型で保証している |
| 医療との線引きは | 診断・治療・処方・緊急対応を行わない。医療の代替ではなく、届かない時間帯を補完する |
| 続かなかったらどうするか | 続かないこと自体を計測対象にしている。中断後再開率と、一般化した非継続理由を見て、次に1つだけ変える |
| 収益化は | 1年目は無料の検証フェーズ。2年目以降に月額コミュニティ等を検討 |
