## 3. 計画している構成（Gate 3 を満たしたら実装する予定のもの）

`docs/account-cloud-storage-decision.md` で確定済みの設計。**この一覧が、オーバースペック点検の対象**。

| 領域 | 計画している構成 |
|------|------------------|
| 実行環境 | 本人記録APIを Vercel Node.js Functions の Singapore（`sin1`）で実行 |
| 認証 | 本人記録専用Neonプロジェクトの Neon Auth。メールのマジックリンク（パスワード・SNSログインなし）。重要操作は直近10分以内の再認証 |
| DB分離 | 匿名分析用Neonとは**別プロジェクト**の本人記録用Neon（AWS Singapore / PostgreSQL 18） |
| 認可 | APIで所有者確認＋PostgreSQL の RLS / FORCE ROW LEVEL SECURITY を第二の防御として全テーブルに適用。CRUD別ポリシー。マイグレーション用ロールと実行時ロールを分離 |
| 暗号化 | TLS・Neonの保存時暗号化に加え、**AWS KMS の顧客管理鍵で利用者ごとにDEKを発行し、記録本文を AES-256-GCM でアプリケーション暗号化**（AADに所有者ID・種別・スキーマ版・改訂番号） |
| 資格情報 | Vercel の Team issuer OIDC → AWS IAM ロールの短期資格情報。長期AWSキーは環境変数に置かない |
| 同期 | 端末優先保存＋同期待ちキュー。複数端末の競合は両版を保持して本人に選ばせる（Last Write Wins は不採用） |
| バックアップ | Neonのスナップショットまたは時点復元、復元試験、削除済みデータの再削除手順 |
| 運用 | 本番権限の四半期棚卸し、二者承認の緊急アクセス、認証失敗・RLS拒否・大量取得・KMS復号失敗の検知 |
| 生成AI | OpenAI API（月2,000円想定） |

### 自分たちで感じている引っかかり

- 利用者は**21名・5か月**。この規模で KMS のアプリケーション層暗号化・鍵ローテーション・四半期棚卸しまで要るのか。
- 「クラウド保存をやらず端末内保存のままにする」ほうが、安全でも安くもなるのではないか。だとすれば**この設計自体を今は実装しない**判断もある。
- Neonプロジェクトを2つに分ける、Vercel を Pro にする、監視SaaSを入れる——どこまでが必須で、どこからが後回しにできるのか自分たちで線を引けない。

## 4. 助けてほしいこと

### お願い① セキュリティに使えるお金が5万円しかない

- **5万円をどこに使うのが一番効くかの優先順位づけ**（例：範囲を絞った有償レビュー／設計レビューのみ／実装後の1点集中チェック）
- **無償・低コストで代替できる確認手順**：OSSツール（依存の脆弱性、シークレット検出、静的解析、ヘッダ検査）、セルフ点検チェックリスト、CI に組み込める自動チェックの型
- **「ここだけは有償でやるべき」という線引き**。逆に「これは自前で十分」の線引きも欲しい
- 可能なら、無償・割引でレビューしてくれる先や制度の心当たり

### お願い② 構成がオーバースペックになっていないか点検してほしい

- 上の構成一覧を見て、**21名・5か月の検証フェーズで「いま必要」「後でよい」「要らない」の3つに仕分け**
- 削減できる固定費の指摘（Vercel Pro は要るか／Neonを2プロジェクトに分ける必要があるか／KMS を使わず Neon の保存時暗号化だけで足りるか／監視SaaSなしで回せるか）
- **「そもそもクラウド保存をやらない」という選択肢の評価**。端末内保存のまま5か月走るのが妥当なら、そう言ってほしい
- 削ってはいけないところ（安全性の下限）を、理由つきで明示してほしい
