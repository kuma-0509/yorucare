## 2. 説明の元になる事実

すべて `docs/account-cloud-storage-decision.md` の決定事項で、実装とも一致している（2026-09-13にPreview実機で確認済み）。

| 項目 | 事実 |
| --- | --- |
| 預けるもの | 日々の記録、「できること」、「やらないこと」、復職日の設定 |
| 預けないもの | 匿名の利用状況、画面の設定、外部AIへ渡した文章、相談内容 |
| 保存場所 | シンガポールのサーバー（Neon。基盤は AWS ap-southeast-1） |
| 暗号化 | 端末を出る前に鍵をかける。サーバーの中身を直接見ても記録は読めない |
| 閲覧できる人 | ログインした本人だけ。運営者が記録を一覧で見る画面も仕組みも無い。**ただし技術的には復号しうる**（下記） |
| 鍵の持ち主 | 記録は利用者ごとの鍵（DEK）で暗号化し、そのDEKを運営者が管理する親鍵（KEK、Vercelの秘密の環境変数）で暗号化して保存する。**つまり運営者は、その気になれば復号できる立場にある**。「運営者は読めない」ではなく「読む仕組みを作っておらず、読まない」が正確 |
| 認証に残るもの | メールアドレス（認証基盤側）。記録とは別に保持される |
| 保存期間 | 本人が消すまで。自動削除はしない |
| 検証終了時 | **全件削除はしない**（2026-09-14の決定）。本人が消すまで預かり続ける。提供を終える場合は事前に知らせる |
| 停止・削除 | 本人がいつでも停止でき、そのときクラウド上の控えも消せる |
| 消したあと | 障害に備えた控えに、鍵のかかったまま一定期間残ることがある |
| 端末内のデータ | クラウドを消しても端末の記録は残る |
| 使える人 | 運営が登録したメールアドレスのみ（許可リスト方式） |

## 3. 参加者向け説明文の草案（配布用）

そのまま配れる文面。アプリ内にも同じ趣旨の説明が出るため、**言葉を揃えてある**（4節参照）。

---

### クラウド保存（記録の控えを預かる機能）について

#### これは何ですか

いまヨルケアの記録は、あなたのスマートフォンやパソコンの中だけに保存されています。そのため、機種を変えたときやブラウザのデータを消したときに、記録が失われます。

クラウド保存は、**記録の控えをインターネット上に預かっておき、新しい端末で取り戻せるようにする機能**です。使うかどうかはあなたが選べます。使わなくても、これまでどおりアプリのすべての機能が使えます。

#### 何を預かりますか

預かるのは次の4つだけです。

- 日々の記録
- 「できること」
- 「やらないこと」
- 復職日の設定

匿名の利用状況、画面の設定、外部のAIへ渡した文章、相談の内容は預かりません。

#### どこに、どのように預かりますか

シンガポールにあるサーバーに預かります。**あなたの端末を出る前に鍵をかける**ため、サーバーの中身を直接見ても記録は読めません。

#### 誰が見られますか

**ログインしたあなただけです。** 運営者が記録を一覧で見る画面や仕組みは作っていません。運営者があなたの記録を読むことはありません。

預けた記録は、**研究や発表に使いません。** 記録の中身が運営者の手元に一覧で集まる仕組みそのものを作っていません。

#### いつまで預かりますか

**あなたが消すまで**預かります。使っていないからといって自動で消すことはしません。プログラムが終わったからといって消すこともしません。

この機能の提供を終える場合は、**事前にお知らせします**。お知らせしてから【要記入: 予告の期間（例: 1か月）】のあいだに、ご自身で記録を書き出していただけます。

#### やめたいとき・消したいとき

アプリの「クラウド保存をやめる」からいつでも止められます。そのときにクラウド上の控えも消せます。**消しても、あなたの端末の記録はそのまま残ります。**

なお、障害に備えた控えの中に、鍵のかかったままの状態でしばらく残ることがあります。期限を過ぎると元に戻せなくなります。

#### ログインについて

ご登録いただいたメールアドレスに6桁のコードをお送りし、それを入力してログインします。パスワードを新しく覚える必要はありません。**メールアドレスは、本人確認のためだけに使います。**

ログインしただけでは、記録は1件も送られません。預けるかどうかは、そのあとで件数を確認してから決められます。

#### 使うかどうかは自由です

使わなくても、プログラムへの参加や支援の内容は一切変わりません。途中でやめても同じです。

#### この機能について気をつけていただきたいこと

ヨルケアの記録はリアルタイムで見守られているものではありません。**医療・緊急支援・危機対応の代わりにはなりません。** 体調が優れないときや緊急のときは、ご自身の判断で医療機関などへご相談ください。

アプリ内には既に同じ趣旨の説明が実装済み（`src/lib/copy.ts` の `cloudBackup`）。**同じことを違う言葉で書かない**こと。食い違うと、どちらが本当か分からなくなる。

**同意の取り方**（2026-09-14に決定）:

参加の形が2通りあるため、**両方の経路で取る**。

| 参加の形 | 同意の取り方 |
| --- | --- |

| アプリだけを使う人 | **アプリ内**で、クラウド保存を使う時点で取得する |

既存の設計（変更なし）:

- ログイン（アカウント作成）と、記録のアップロードは**別の操作**にしてある。
- 件数を示したうえで本人が「この内容を預ける」を押した時点を、アップロードへの明示同意として扱う（`docs/account-cloud-storage-decision.md` 15節、2026-09-09の決定）。
- クラウド保存の同意と匿名分析の同意は別々に管理する。片方を変えても、もう片方は変わらない。

**この決定に伴って必要になる実装**（未着手）:

いまアプリが覚えているのは「同意したかどうか」だけ（`src/lib/cloud-consent.ts`、端末内に `granted` / `denied` の文字列）。**いつ同意したか、どの文面に同意したかは残っていない。** 同意を取った証拠として扱うには、少なくとも次が要る。

1. 同意した日時
2. 同意した時点の説明文の版（文面を直したら版を上げる）
3. 端末を変えても消えないこと（端末内だけだと、ブラウザのデータを消せば同意の記録も消える）

3をどこまでやるかは、5.1の確認結果（要配慮個人情報に当たるか）で変わる。当たる場合は記録を残す必要性が高い。**文面が確定してから実装する**（先に作ると版番号を付け直すことになる）。

## 5. 確認が要る論点

法令の当てはめは専門家の確認が要る。ここでは**何を確認すべきか**と**なぜそれが論点になるか**を整理する。断定はしない。

### 5.1 記録が「要配慮個人情報」に当たるか

ヨルケアの記録には、休職・復職の状況、気分、睡眠、体調に関する内容が含まれる。これらが**心身の状態や病歴に関する情報**と評価される場合、個人情報保護法上の「要配慮個人情報」に当たり、**取得にあたって本人の同意が必須**になる（オプトアウトによる第三者提供もできない）。

- 当たる場合: 3節の説明に加えて、**取得への同意を明示的に取る**運用（書面または電子的な同意記録）が要る。アプリ内の操作だけで足りるかを確認する。
- 当たらない場合: 現在の設計（件数を示したうえでの明示操作）で足りる可能性が高い。

**論点にする理由**: すでに端末内には同じ情報を保存しているが、クラウド保存は事業者側が保有する状態になるため、扱いが変わりうる。

### 5.2 シンガポールのサーバーへの保存（外国への移転）

保存先が国外（シンガポール）であるため、**外国にある第三者への提供**の規律が関係する。処理の委託であっても、この越境の規律は別途かかると理解されている。

本人の同意による場合、一般に次の情報提供が求められる。

1. 移転先の国の名称（シンガポール）
2. その国の個人情報保護制度に関する情報
3. 移転先が講じる個人情報保護のための措置

3節の草案には(1)を書いてある。**(2)(3)をどこまで書くか**を確認する。基準適合体制の整備によって対応する道もあるため、どちらで行くかを決める。

**論点にする理由**: 保存先の国は実装上すでに確定しており（Neon / AWS ap-southeast-1）、後から変えるのは容易ではない。文面に書く内容だけの問題として早く確定させたい。

### 5.3 委託先の監督（Neon・Vercel）

記録の保存をNeon、アプリの配信をVercelに委ねている。委託先を選ぶ理由と監督の方法を記録しておく必要がある。

確認・記録すべきこと:

- 契約条件、保存国、再委託先、保持期間、削除条件（`docs/account-cloud-storage-decision.md` 11.2節に既に条件として記載あり）
- 事故が起きたときの連絡経路
- Managed Better Auth が**ベータ版**であること（同文書に記載）。ベータのまま参加者に使わせてよいかの判断

### 5.4 研究としての扱い

**発表する予定はある。発表先は未定**（2026-09-14の回答）。確認は発表先が決まってから行う。

クラウド保存については、この後回しでも矛盾は小さい。**クラウド保存は研究データの収集経路ではない**（本人の記録を本人のために預かるだけで、運営者の手元に記録が一覧で集まる仕組みを作っていない）ためである。3節の説明文にも「預けた記録は研究や発表に使いません」と明記した。

**ただし、次の点は発表先が決まる前に意識しておく必要がある。**

- 倫理審査が要る種類の研究の場合、**審査はデータを集める前に受けるのが原則**である。発表先が決まってから審査に出すと、それまでに集めた内容を使えない恐れがある。発表の可能性があるなら、**発表先が未定のうちに所属機関へ「この内容で研究になるか」だけ先に相談しておく**のが安全。
- 参加者への説明に「発表する可能性がある」ことを書かずに進めると、後から同意を取り直すことになる。これは**プログラム全体の参加説明**の話であり、クラウド保存の説明文の範囲ではない。プログラム側の説明文書を確認すること。

### 5.5 預かり続けることに伴う責任（方針変更あり）

当初の決定（8.1節）は「検証終了日に運営者が全件削除する」だったが、2026-09-14に**削除しない（本人が消すまで預かり続ける）**方針へ変えた。機種変更で記録を失わないための機能なのに、運営の都合による期日で消えては目的を果たさないためである。

**この変更で新しく生まれる責任**を意識しておく。

- **終わりが無くなる。** プログラムが終わっても預かり続けるため、サーバー費用と管理が続く。無料枠を超えたときにどうするかを決めておく。
- **やめるときの約束が要る。** 提供を終える場合は事前に知らせると説明文で約束した。**予告の期間を決める**（7節）。
- **連絡手段が要る。** 予告するには参加者へ連絡できる必要がある。認証に使うメールアドレスを連絡に使ってよいかは、3節の「メールアドレスは本人確認のためだけに使います」と食い違わないように決める。→ **予告のときだけは使う**と説明文に書き足すか、別の連絡経路（プログラム側の連絡先）を使うかを決める。

### 6.1 研究・倫理面（所属機関の担当部署、研究責任者）

> ヨルケア（復職支援のセルフケア記録アプリ）に、参加者本人が自分の記録の控えをクラウドへ預けられる機能を追加したいと考えています。記録は暗号化して保存し、**運営者が記録を一覧で見る仕組みは作っていません**（ただし鍵の管理は運営者側にあるため、技術的には復号しうる立場です）。研究データとして収集・分析する予定はありません。この機能を現在の5か月間プログラムの参加者に提供する場合、
> 1. 人を対象とする研究の倫理指針の対象になりますか。倫理審査は必要ですか。
> 2. 参加者への説明文書と同意の取り方は、現在の様式に追記する形でよいですか。
> 3. 記録に休職・復職の状況や体調が含まれるため、要配慮個人情報として扱うべきか、判断を伺えますか。

### 6.2 個人情報の取扱い（法務・個人情報保護の担当者、または専門家）

> セルフケア記録アプリで、本人の記録（気分・睡眠・体調・復職日など）を、本人の操作でクラウドへバックアップする機能を追加します。前提は次のとおりです。
> - 保存先はシンガポールのマネージドPostgreSQL（Neon、基盤はAWS ap-southeast-1）
> - 記録は利用者ごとの鍵で暗号化して保存する。その鍵は運営者が管理する親鍵で保護しているため、**運営者は技術的には復号しうる立場にある**（読むための画面や仕組みは作っていない）
> - 認証にはメールアドレス（6桁コード方式）を使い、認証基盤にメールアドレスが保持される
> - 本人はいつでも停止・削除できる。期日による一括削除は行わず、本人が消すまで保持する
> - 利用者は運営が登録した参加者のみ（許可リスト方式）
> - 事業者は個人（熊谷祐希）であり、大きな組織の体制はない
>
> 確認したいこと:
> 1. この記録は要配慮個人情報として扱うべきですか。その場合、取得の同意はどのような形で取るべきですか。
> 2. 外国（シンガポール）への移転として、本人同意によるか、基準適合体制の整備によるか、どちらで進めるべきですか。本人同意による場合、説明文に書くべき内容を教えてください。
> 3. 委託先（Neon・Vercel）の監督として、記録しておくべき事項を教えてください。
> 4. 本人からの同意は、Googleフォームとアプリ内の操作の2経路で取る予定です。同意の記録として何を残すべきですか（日時、同意した文面の版など）。
