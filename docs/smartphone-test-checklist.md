# ヨルケア スマホ実機テストチェックリスト

**目的**: 公開 URL 上で、毎日 1〜2 分の記録体験がスマホで使えるかを検証する。
**対象**: 現行の `main`（Phase 1 MVP の記録・一覧・グラフ ＋ Phase 2 P1 の 3 段階の入口、目標のふりかえり、自分メンテ、週のまとめ、積み重ね表示）
**想定時間**: 参加者 1 人あたり約 5 分（B-0 のみ）/ 実施者の全項目確認 約 35〜45 分

**判定の基準**（`docs/phase2-plan.md` 3.3 節）

- 5 人中 4 人以上が、補助なしで基本記録を **2 分以内** に保存できる。
- 5 人中 4 人以上が、過去の記録から **週の状態を振り返る場所** へ到達できる。
- データ消失、意図しない共有、保存不能、相談導線へ到達できない問題を **重大不具合** とする。

**上の 2 つは B-0（無誘導の計測）でしか測れない。** B-0 は参加者 1 人につき 1 回だけで、やり直しがきかない。**B-0 を行う前に、この文書の B-1 以降を参加者に見せない。**

**注意（データの前提）**

- データは **この端末のこのブラウザだけ** に保存される。
- 別端末・別ブラウザ・キャッシュ削除でデータは共有されない / 消える可能性がある。
- テスト用のダミーデータで実施する。実際の健康・服薬・面談内容は入力しない。

### 見本データの用意（C-10・F・G-7）

C-10（前日の目標のふりかえり）、F（積み重ね・週のまとめ）、G-7（旧形式からの復元）は、**その場の入力だけでは確かめられない**。前日の目標、数日分の記録、復職日を持たないファイルが要る。手で作ると人によって中身が変わり、行ごとの母数（F-17）や連続日数（F-7）が出たり出なかったりする。

PC で次を実行すると、**その日を起点にした見本データ**が 2 つできる。

```sh
pnpm testdata --out ./testdata   # node scripts/make-test-data.mjs --out ./testdata と同じ
```

| ファイル | 中身 | 使う場所 |
|----------|------|----------|
| `yorucare-testdata.json` | 1・2・3・5 日前の記録（4 日前は空ける）、できること 5 件、復職日（10 日前） | C-10 / F / G-7 の前提 |
| `yorucare-testdata-legacy.json` | 上と同じ記録で、**復職日のフィールドだけがない**旧形式 | G-7 |

- 日付は実行した日から数えるので、**テストの当日に作る**（前に作ったものは直近 7 日から外れて「これまで」に出ない）。
- 作ったファイルをテスト端末から開ける場所（クラウドドライブ、メール添付、端末へ直接コピー）に置く。
- 読み込みは **「これまで」→「保存したファイルから復元する」→「復元する」**。**確認ダイアログで「復元する」を押すまで置き換わらない。**
- **復元すると、端末にある記録と「できること」はファイルの内容に置き換わる。** それまでに入力したものを残したいときは、先に「記録をファイルで保存する」で書き出す。
- 見本に入っているのはダミーだけで、実在の体調・服薬・面談の内容は含まない。自由記述（メモ、しんどさの自由記述、できることのメモ）は空にしてある。
- 見本が上の条件を満たしていることは `src/lib/smartphone-test-data.test.ts` で固定してある。

## B. 今日の記録 — 無誘導の計測と保存後（約 6 分）★最重要

`docs/phase2-plan.md` 3.3 節の判定基準（**補助なしで** 2 分以内に保存、**過去の記録から週の状態を振り返る場所へ到達**）を測る章。

**この章は 2 つに分かれる。**

- **B-0**: 参加者に実施してもらう無誘導の計測。**操作を教えない。** Gate 1 の判定根拠はここでしか作れない。
- **B-1 以降**: 実施者が 1 人で通す機能確認。操作を明示してよい。

**B-0 は 1 人につき 1 回しか測れない。** 一度やり方を見た人を「初めて触る人」に戻すことはできず、参加者は 5 人しかいない。**B-0 より先に B-1 以降を参加者に見せると、その人ぶんの計測は作り直せない。**

## 「不具合ではない」こと

| 現象 | 理由 |
|------|------|
| ログイン画面がない | Phase 1 スコープ外 |
| 一覧が直近 7 日しか出ない / それより前を編集できない | 直近 7 日のみ表示・編集可 |
| 別端末でデータが見えない | この端末のブラウザ内にだけ保存する |
| ヨルケアから外部 AI へ自動送信されない | 本人が全文を確認して共有先を選ぶ形だけを用意している |
| 「いま何日続けて書けているか」が出ない | 中断を失敗として見せないため、中断で減らない累計だけを出す |
| 節目のねぎらいが毎日出ない | ちょうど届いた日だけ出す。記録した日の節目は、その日に記録を保存したときだけ出る |
| 「これまでの記録を見る」が保存直後に見えない | 保存後の完了画面にだけ出る |
| 週のまとめの行ごとに母数の数字が違う | 行ごとに、その項目へ答えられた日数を母数にしている（F-17 の表） |
| 前日の目標のふりかえりが出ない日がある | 前日に目標を書いた日だけ出す |
| 自分メンテのカードが出ない | その日の状態（3 段階）をまだ選んでいないとき |
| 週のまとめに割合（％）が出ない | 母数の小さい割合を避け、日数で示す |
| リマインド通知がない | `docs/reminder-decision.md` の Gate 2 を満たすまで実装しない |
| 最初にレビュー同意の画面が出る | レビュー用ビルドだけが持つ画面。閉じるには「同意してレビューを始める」を押す（A-12）。B-0 では実施者が先に閉じてから渡す |
| 復元すると今ある記録が置き換わる | ファイルの内容へまるごと入れ替える動きにしている。残したいものは先に「記録をファイルで保存する」（G-5・見本データの節） |
| 節目の見出しが「はじめてから」と「復職から」で変わる | 復職日を設定すると起点が変わるため、見出しも合わせて変わる（F-9・F-11） |
| 週のまとめに「続けて記録できた日」が出たり出なかったりする | 続けて 2 日以上書けた期間だけ出る（F-17） |
