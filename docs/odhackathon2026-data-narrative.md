# 支援の空白を証明するデータ設計

作成日: 2026-08-04
状態: 設計中（データの一次確認が未了）
関連: `docs/odhackathon2026-plan.md`

## 0. この文書の目的

「窓口が閉まっている」だけでは、ヨルケアの有用性は示せない。示すべきことは3つある。

1. **需要**: 窓口が閉まっている時間帯に、支援を要する状態が実際に集中している
2. **供給**: その時間帯に到達できる公的窓口がない
3. **効用**: アプリで状況を整理・言語化することが、当事者・医療機関・支援者・行政窓口のいずれにとっても利益になる

1と2の突き合わせが「空白」、3が「なぜアプリなのか」にあたる。本書は各主張に対して、どのオープンデータで、どのロジックで裏付けるかを定める。

**未確認**: 環境のネットワーク制限により、以下のデータセットは検索結果から特定したもので、列構成・粒度・ライセンスの一次確認ができていない。実装前に必ず実物を確認する。

## 1. 需要側 — いつ、支援が必要になっているか

### 1-1. 死亡曜日別の自殺者数（人口動態統計）

死亡曜日別の一日平均自殺者数は**月曜日が最多**とされる（男71.2人・女25.4人）。出典は人口動態統計の第1-36図。

これは、ヒアリングで得られた当事者の言葉と正面から一致する。

> 「週末で回復させても、**月曜日が怖い**」が繰り返され、再休職のトリガーになる
> （`docs/evidence/vha2026-entry-summary.md`）

**質的な訴え（ヒアリング）と量的な事実（公的統計）が同じ方向を指している。** これは提案として最も強い形であり、2分のプレゼンでも1行で言い切れる。

さらに重要なのは、ヨルケアの既存プログラムが**日曜21:00の振り返りの会**を既に置いていることである。「日曜は翌週への弾み」という設計判断が、後から公的データで裏付けられた構図になる。狙って作ったものが、データで正しかったと確認できる。

#### 取り扱いの厳格な制約

自殺統計は、**需要が発生する時点を示す目的にのみ使う。**

- ヨルケアが自殺を予防する、減らす、という主張は**絶対にしない**
- ヨルケアは危機介入をしない。危険度の推定もしない（`docs/consultation-routing.md`）
- 「つらさが特定の曜日・時間帯に偏る」という事実の提示に留め、因果や効能へ踏み込まない

この線を越えると、医学的効能の主張になり（`AGENTS.md` の禁止事項）、かつ危機対応サービスだという誤認を生む。提案の信頼性を最も損なうのはここなので、資料の文言も本節の枠内に収める。

### 1-2. 時間帯別の救急出場件数（東京消防庁）

東京消防庁「救急活動の現況」に時間帯別出場件数の図表がある（令和5年版 図表1-17、PDF/Excel）。東京都オープンデータカタログの組織ページは `t000017`。

都内の需要が時間帯でどう動くかを示す材料になる。急病全般であり精神的不調に限られない点は、そのまま断って使う。

### 1-3. 生活時間（社会生活基本調査）

就業者の帰宅時刻・睡眠時間の分布。「支援が閉まる時間から、本人の自由時間が始まる」という構造を示す。需要の強度ではなく、**本人がアプリに向かえる時間帯**の裏付けとして使う。

## 2. 供給側 — いつ、窓口が開いているか

`docs/odhackathon2026-plan.md` の通り。自治体標準オープンデータセット「公共施設一覧」の `available_day` / `start_time` / `end_time` を主データとし、東京都「社会福祉施設等一覧」で窓口の実体を補う。

判定ロジックは `src/lib/facilities/opening-hours.ts` に実装済み。受付時間が不明な施設を閉として数えない。

## 3. 空白指数 — 需要と供給を突き合わせる

曜日×時間帯のセルごとに、次を並べる。

| 値 | 意味 |
|---|---|
| `demand` | その時間帯の需要の相対値（0〜1に正規化） |
| `open` / `closed` / `unknown` / `total` | その時間帯の窓口の内訳 |
| `gapScore` | 需要が高く、かつ開いている窓口が少ないほど大きい |

### 独立性の仮定を隠さない

需要側のデータは、**曜日別と時間帯別が別々の表で提供される**ことが多い。この場合、曜日×時間帯の同時分布は分からない。周辺分布の積で埋めることはできるが、それは「曜日と時間帯が独立」という仮定を置いたことになる。

実際には独立ではない可能性が高い（平日の深夜と日曜の深夜は事情が違う）。したがって、

- 同時分布が得られたセルと、周辺分布の積で推定したセルを**別のフラグで区別する**
- 推定値であるセルは、画面と資料の両方で推定と明示する
- 推定を根拠に断定的な主張をしない

数値の由来を型で持ち回る方式は、`src/lib/ai/period-summary.ts` が母数を必ず返すのと同じ考え方による。**確からしさの違う値を同じ見た目にしないこと**を、運用ルールではなくデータ構造で守る。

## 4. 効用 — 言語化がなぜ四方にとって利益になるか

「アプリで記録する」ではなく「**限られた接点の質を上げる**」と捉え直すと、各者の利益が同じ構造で説明できる。共通しているのは、**接点が短く、間隔が空いている**という制約である。

| 相手 | 制約（データで示す） | 言語化された記録が効く理由 |
|---|---|---|
| **当事者** | 精神障害者の入社1年後の職場定着率 **49.3%**。離職理由は「疲れやすく体力、意欲が続かなかった」「症状が悪化（再発）した」が**各約3割**（障害者職業総合センター 調査研究報告書No.137） | 悪化は突然ではなく積み重なる。夜間・休日の状態を残せれば、本人が予兆を捉えられる |
| **医療機関** | 受療行動調査（e-Stat、3年周期）に診察時間・説明の程度・満足度の分布がある | 診察時間は短い。前回受診からの経過が整理済みで持ち込まれれば、限られた時間を判断に使える |
| **支援者** | 支援面談は月1回（ヒアリング）。面談は「仕事ができているかの確認で精一杯」 | 28日分の空白を口頭で再構成する必要がなくなり、面談を確認から対処へ振り向けられる |
| **行政窓口** | 公共施設一覧が示す受付時間。夜間・休日は開いていない | 窓口が開く時間に、整理された状態で相談が来る。短い応対で要点に入れる |

### 主張の限界

これらは「記録があれば接点の質が上がりうる」という設計上の説明であり、**効果が検証済みという主張ではない**。VHAの実践研究（約20名、PHQ-9・UWES-9・WHO-HPQ・PSQI）はこれからであり、資料でも検証前であることを明記する。

「支援者・医療機関にとってのWin」は、**共有された場合に限って**生じる。ヨルケアの共有は本人の明示操作に限られ、記録を自動送信しない（`docs/sharing-decision.md`）。Winの説明が、勝手に共有される仕組みだと誤解されないようにする。

## 5. 2分プレゼンへの落とし方

| 枚 | 主張 | 使うデータ |
|---|---|---|
| 2 | 復職後、夜間・休日に落ちる。**月曜が最も重い** | 死亡曜日別の自殺者数、時間帯別救急出場件数 |
| 2 | その時間、公的窓口は開いていない | 公共施設一覧の受付時間 → ヒートマップ |
| 3 | だから、その時間に本人が使えるものが要る | ヨルケアの画面 |
| 5 | 記録は接点の質を上げる。四方にWin | 職場定着率49.3%、受療行動調査 |

課題（枚2）で需要と供給を1枚に重ねられれば、空白の説明は10秒で済む。ヒートマップ1枚に両方を載せる設計を優先する。
