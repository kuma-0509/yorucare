## 実装指示文

あなたは、Next.js・TypeScript を用いた福祉・ヘルスケア領域のプロダクト開発に強い
シニアフルスタックエンジニア兼 UX デザイナーです。

既存の「ヨルケア」を、東京都オープンデータ・ハッカソン応募を想定して拡張してください。
新しいアプリを作るのではなく、既存プロダクトの設計思想を壊さずに機能を足します。

### 0. 着手前に必ず読むもの

- `AGENTS.md`（提案・エビデンス、開発管理のルール）
- `docs/DEVELOPMENT_BOARD.md`（関連課題の現在の進捗。着手前に確認し、完了前に更新する）
- `docs/consultation-routing.md`（相談導線の境界。今回の中心的な制約）
- `docs/phase2-plan.md` 第2章「変えない前提」
- `src/lib/ai/weekly-summary.ts` 冒頭コメント（文面生成の4つの制約）

技術スタック（Next.js 15 App Router / TypeScript / Tailwind / shadcn/ui 相当 / Zod /
Vitest / pnpm / Vercel / ログイン不要 / localStorage）は README に記載済みなので、
調査は次の4点に絞ってください。

1. `src/components/app-shell.tsx` の4タブ構成に、新機能をどう配置するか
2. `src/lib/repository.ts` の `Promise<Result<T>>` 境界の使い方
3. `src/lib/consultation-resources.ts` の既存相談先（全国窓口）と東京都データの関係
4. `src/lib/copy.ts` と `src/components/shared/selection-control.tsx` の契約

### 1. コンセプト

「本人の記録から生活の変化に気づき、東京都の相談・医療・福祉データを使って、
その時間に開いている支援先を本人が選べるようにし、状態に応じた無理のない
運動をセルフケアの選択肢として提示する」

対応テーマ:

1. こころの不調に気づき、適切な相談・ケアにつながる仕組み
2. 症状、緊急度、時間帯に応じた相談・医療への案内
3. 身近でできる運動など、無理のない健康づくりの提案

ただしテーマ2の「緊急度」は、**アプリが判定するのではなく本人が選ぶ**ものとして
実装します。これは `docs/consultation-routing.md` で確定済みの境界です。

### 2. 絶対に守る制約（既存設計の中核）

- アプリは診断・治療・処方、危機判定、24時間監視の代替ではない
- **入力内容から危険度・緊急度を推定しない**
- 評価語（よい・悪い・改善・悪化）と助言（〜しましょう）を出力しない
- 記録がなかった日を「抜けた」「できなかった」と書かない
- 数値には母数を添え、割合ではなく日数で示す
- 本人の記録を端末外へ送信しない。匿名利用イベントに新機能の入力内容を載せない
- 確認できていない電話番号・施設情報を作らない。デモデータは架空の電話番号を持たず、
  画面上で「デモデータ」と明示する
- 画面文言は `src/lib/copy.ts` に追加し、コンポーネントへ直書きしない

### 3. 実装しないもの（既存にあるため）

記録入力、`DailyRecord` 型、localStorage 保存、スキーマ検証、バックアップ、
記録の削除、週次まとめ、ふりかえりグラフ、相談文テキスト生成（`ai-share-text.ts`）、
モバイル対応、日本語UI、ログイン不要構成。

既存の記録項目（`moodScore` / `sleepMinutes` / `medication` / `warningLevel` /
`warningTags` / `selfCareIds`）だけで今回の機能を成立させてください。
`DailyRecord` へのフィールド追加は原則行いません。追加が不可避と判断した場合は、
実装前に理由と1〜2分の入力時間への影響を報告してください。

### 4. 実装するもの

#### 機能A: 記録から見える変化の提示（判定ではない）

直近7日の記録から、**事実だけ**を列挙します。状態のラベル付けはしません。

出力例:

- 「気分が『少ししんどい』以下だった日: 7日中4日」
- 「睡眠時間の中央値: 5時間20分（記録があった5日分）」
- 「お薬を『忘れた』と記録した日: 2日」
- 「しんどさのサインで最も多かった項目: 朝起きづらい（3日）」

実装:

- `src/lib/ai/period-summary.ts` `frequency.ts` `streaks.ts` を再利用する
- 変化検出は `detectChanges()` として独立モジュールに置く
- 閾値は設定ファイルに集約し、コード内に散在させない
- 対象0件のときは0ではなく null を返し、「値が低い」と「データがない」を区別する
- 表示には「これは診断ではなく、本人の記録の集計です」を必ず添える

「相談先を見る」は、変化の有無にかかわらず**常に同じ場所に同じ強さで**置きます。
変化が多い日だけ強調表示することは、アプリによる危険度推定にあたるため行いません。

#### 機能B: 東京都の相談・医療・福祉機関の案内

既存のヘッダー常設「相談先」ダイアログを拡張し、東京都内の支援先を検索できるようにします。
既存の全国窓口（119 / 110 / #いのちSOS / 厚生労働省リンク）は表示順1〜2位のまま維持します。

本人が選ぶ条件:

- 現在いる市区町村
- 相談したい内容（こころの健康 / 医療機関 / 就労・生活 / 発達障害 / 福祉窓口）
- 相談方法（電話 / オンライン / 対面）
- いつ相談したいか（今すぐ / 今日中 / 数日以内）

現在時刻と曜日から表示するもの:

受付中 / 本日は受付終了 / 次回受付日時 / 24時間対応 / 予約要否 / 相談方法。

並び順:

1. 本人が選んだ緊急度との適合
2. 現在受付中か
3. 市区町村の適合
4. 相談内容の適合

型は `SupportResource` として定義します（`latitude` / `longitude` / `address` は
MVPでは持ちません）。

```ts
type SupportResource = {
  id: string;
  name: string;
  category:
    | "emergency"
    | "nightConsultation"
    | "mentalHealth"
    | "medical"
    | "welfare"
    | "employment"
    | "developmentalDisability";
  description: string;
  prefecture: string;
  municipality?: string;
  phone?: string;
  websiteUrl?: string;
  consultationMethod: Array<"phone" | "online" | "inPerson">;
  targetUsers?: string[];
  availableDays?: number[];
  openingTime?: string;
  closingTime?: string;
  is24Hours?: boolean;
  reservationRequired?: boolean;
  source: DataSource; // 出典とデモ／実データの別
};
```

安全に関する案内（一人にならない、119・110、公的窓口、安全な場所へ移動）は、
入力内容をトリガーに自動表示するのではなく、ダイアログ最上部に常設します。

#### 機能C: 状態に応じた運動の提案

`docs/DEVELOPMENT_BOARD.md` の未着手課題「自分メンテ」に該当します。
新しい並列機能ではなく、**既存の「できること」辞書の延長**として実装してください。

その日の記録（気分・睡眠・しんどさのサイン）から、負担の軽い順に候補を出します。

- レベル0（休息優先）: 「今日は休む」を最初の選択肢として提示する
- レベル1（1〜3分）: 深呼吸、肩を回す、水分を取る、窓を開ける
- レベル2（5〜10分）: 室内ストレッチ、家の周りを短く歩く
- レベル3（10〜30分）: ウォーキング、公園への散歩、近隣スポーツ施設

制約:

- 提案であって処方ではない。「〜しましょう」ではなく「〜という選択肢があります」
- 「今日は休む」は代替ではなく**対等な選択肢**として同じ大きさで置く
- 実施しても実施しなくても、達成率・連続日数として集計しない
- 体調が悪いときは中止する旨、痛み・息苦しさがあれば医療機関へ相談する旨を添える

#### 機能D: 既存の相談文生成との接続

`src/lib/ai-share-text.ts` を再実装せず、生成テキストに以下を追加できるようにします。

- 機能Aで出した事実（母数付き）
- 参照した相談先の名称（本人が選んだ場合のみ）

`docs/ai-consent-decision.md` の方針どおり、本人が書いたメモ本文を新しい経路へ
出さないでください。方針は運用ルールではなく、戻り値型に本文フィールドを
持たせないことで保証します。

### 5. データアダプター

東京都オープンデータの実URL・API仕様が確認できない場合、推測して実装しないでください。
将来差し替えられるアダプター層を用意し、MVPはローカルJSONで動かします。

想定データセット（将来接続先として設計だけしておく）:

- 東京都の相談窓口・保健所・精神保健福祉センター一覧
- TOKYO WALKING MAP / 都立公園・庭園 / 都立スポーツ施設

すべての外部データに `DataSource`（提供者 / データセット名 / 更新日 / 参照URL /
デモか実データか）を持たせ、画面に「データについて」を設けます。
更新日が古い可能性がある場合は、利用前に公式サイトか電話で確認するよう案内します。
オープンデータのライセンス表記が必要な場合はそれも表示してください。

個人の記録データ（`src/lib/repository.ts` 配下）と外部公開データは、
モジュールとして明確に分離してください。

### 6. 進め方

1. 実装前に、簡潔な計画（変更ファイル・4タブへの配置・新規型）を提示する
2. `docs/DEVELOPMENT_BOARD.md` の関連課題を確認する
3. 型定義 → デモデータ → 変化検出 → 相談先検索 → 運動提案 → 相談文接続 の順に実装する
4. Vitest で単体テストを追加する
   - 変化検出: 母数が足りない期間で null を返す / 未記録日を「できなかった」と書かない
   - 相談先: 受付中が優先される / 市区町村で絞れる / 営業時間外に次回受付が出る
   - 運動提案: しんどさが強い日に高負荷を出さない / 「今日は休む」が常に選べる
   - 文言: 評価語と助言表現が出力に含まれないことを検証する
5. `pnpm lint` `pnpm test` `pnpm build` をすべて通す
6. README と `docs/DEVELOPMENT_BOARD.md` を更新する（`AGENTS.md` の必須事項）

### 7. UI・UX

夜間でも見やすい配色、1画面1目的、色だけに依存しない状態表示、キーボード操作と
読み上げ対応、44px以上の操作領域、過剰なアニメーションを避ける。
不安をあおる赤色表現は使わない。「異常」「重症」などスティグマを生む語を使わない。

### 8. 完了報告

1. 変更ファイル
2. 実装した機能
3. 変化検出のルールと閾値の置き場所
4. 使用データとデモ／実データの区別
5. テスト結果（lint / test / build）
6. 残課題
7. 東京都オープンデータへ本接続するために必要な作業
8. 既存の設計思想（危険度を推定しない・評価語を出さない）を守れているかの自己確認

不明点があっても作業を止めず、安全な仮定を明示して差し替え可能な設計で進めてください。
ただし、URL・電話番号・医療機関情報の創作は一切行わないでください。

## 原案からの変更点

| 原案の指示 | 問題 | 対応 |
| --- | --- | --- |
| 状態を「安定／注意／要相談」で判定する | `src/lib/ai/weekly-summary.ts` が「評価語と助言を出さない」を層の責務として実装済み。「無理をせず休みましょう」等の表示例は正面から衝突する | ラベル判定を廃止し、母数付きの事実提示に置換 |
| 希死念慮の確認項目を記録へ追加する | `docs/consultation-routing.md` の「アプリは入力内容から危険度を推定しない」「24時間監視・危機対応を提供しない」に反する。応答する人がいないアプリで危機を尋ねると、応答されるという期待だけが生まれる | 質問しない。本人発意で開ける相談導線の常設を強化する |
| 緊急度で並び替え、該当時に安全確認画面へ自動遷移する | 同上。アプリが緊急度を確定させる設計になる | 本人が選んだ緊急度での絞り込みに変更。安全案内は常時到達可能な固定表示にする |
| 睡眠満足度・人と話したか・運動実施を記録項目へ追加する | `docs/phase2-plan.md` の検証仮説が「1日1〜2分の記録負担」。項目追加は仮説自体を壊す | 新規フィールドを追加しない。運動実施は既存の「できること」辞書で表現する |
| 緯度経度・住所・地図ボタン | MVPの範囲を超え、データ最小化の方針にも合わない | 市区町村の選択のみとする |
| 記録機能・型定義・localStorage・削除機能・相談文生成・モバイル対応・ログイン不要構成を実装する | いずれも実装済み（`repository.ts` / `schemas.ts` / `ai-share-text.ts` / `data-backup-panel.tsx` ほか） | 「既存を使う」に変更 |
| 12項目の事前調査リスト | 大半が README と `AGENTS.md` に記載済み | 4点に圧縮 |

原案に不足していて追記した事項:

- `AGENTS.md` が定める `docs/DEVELOPMENT_BOARD.md` の着手前確認と完了前更新
- 画面文言は `src/lib/copy.ts` を単一基準とすること
- 選択UIのアクセシビリティ契約は `src/components/shared/selection-control.tsx` にあること
- 既存相談先が全国窓口（厚生労働省）であり、東京都データとの表示順の整合が必要なこと
- 新機能の入力内容を匿名利用イベントへ載せないこと
- オープンデータのライセンス表記
