# Cowork タスク連鎖プロンプト（1チャット＝1タスク）

1つのチャットで開発タスクを1件だけ進め、コミットしたうえで次のチャットへ引き継ぐための定型プロンプト集。
タスクの正本は `docs/DEVELOPMENT_BOARD.md`、チャット間の引き継ぎ内容は `docs/handoff/latest.md` に置く。

---

## 0. 残タスクと推奨順序（2026-08-06 時点）

AI が単独で進められるタスクを、依存関係の順に並べたもの。順序を変える場合は理由を引き継ぎメモに残す。

| # | 課題（管理表の行） | 現在の進捗 | 依存 |
| --- | --- | --- | --- |
| 1 | 入力項目が多いと毎日の記録を続けにくい（3段階の状態選択で追加質問を絞る） | 未着手 | なし |
| 2 | 翌日に目標や行動実験を振り返る導線が弱い（目標機能の実装） | 未着手 | #1 と同じ入力画面を触るため #1 の後 |
| 3 | 週次まとめに目標の達成状況を含められない | 未着手 | #2 が前提 |
| 4 | 記録した状態からセルフケア行動へつなげる「自分メンテ」が不足 | 未着手 | #1 |
| 5 | 継続や積み重ねを実感しにくい（継続日数・活動日数・節目表示） | 未着手 | なし |
| 6 | LLM呼び出しと報告書出力が未実装（穴埋め方式） | 未着手 | `src/lib/ai/*` は実装済み |
| 7 | R3F版「本棚にしまう」演出の品質向上 | 改善中 | なし |
| 8 | 記録完了演出を本番フローへ統合 | 未着手 | #7 |
| 9 | 本棚演出の質感と没入感の高品質化 | 未着手 | #7 |

AI だけでは完了にできないタスク（実機・利用者確認が必要。チャットでは着手せず、確認手順の整備までに留める）

- スマートフォン実機テストの実施結果が文書化されていない（`確認待ち` の実施者は人間）
- R3F版「本棚にしまう」改善版のユーザー確認が必要
- R3F版「本棚にしまう」演出の実機品質とパフォーマンスが未確認

着手しないタスク（ゲート待ち・判断済み）

- Gate 2 通過後のリマインド機能（`保留`）
- Gate 4 通過後の期限付き共有リンク（`保留`）
- 「ゴミ箱へ捨てる」「記録が溜まったら燃える」演出（`後回し`。管理表の `判断済み` 行で着手を禁止）

## 1. 最初のチャットに貼るプロンプト

```
このリポジトリ（yorucare）の開発を、1チャット1タスクで順番に進めます。あなたは1件目を担当します。

まず読むもの
- AGENTS.md
- docs/DEVELOPMENT_BOARD.md
- docs/phase2-plan.md
- docs/cowork-task-relay-prompt.md（この進め方の定義）

やること
1. docs/DEVELOPMENT_BOARD.md の残タスクを確認し、docs/cowork-task-relay-prompt.md の推奨順序が今も妥当か判断する。ずれていれば理由と一緒に修正案を示す。
2. 1件目のタスク「<タスク名>」だけを実装する。他のタスクには手を出さない。
3. 実装後に pnpm lint / pnpm test / pnpm build を通す。落ちたら直してから次へ進む。
4. docs/DEVELOPMENT_BOARD.md の該当行（進捗・改善方法・完了日）を同じ作業内で更新する。完了にした行だけ完了日を YYYY-MM-DD で書く。
5. docs/handoff/latest.md を新規作成し、末尾の「引き継ぎメモの書式」に従って書く。
6. コミットして push する。コミットは課題単位で1つにまとめ、メッセージは日本語で「feat: 〜」「fix: 〜」「docs: 〜」の形にする。
7. 最後のチャット出力として、次のチャットにそのまま貼れる引き継ぎプロンプトを、コードブロックで出力する。

守ること
- 記録本文・健康・服薬・面談に関する情報、個人を特定できる情報を、管理表・引き継ぎメモ・コミットメッセージに書かない。
- DailyRecord や schemas.ts を変更する場合は、スキーマ版の移行と既存データの読み込み互換を必ず用意する。
- 診断・治療の代替と読める文言を UI に出さない。未入力や中断を失敗として扱う表現を出さない。
- 1チャットで2件以上のタスクを進めない。範囲外の改善を見つけたら、実装せず管理表に課題として1行足す。
```

`<タスク名>` は `docs/DEVELOPMENT_BOARD.md` の課題名をそのまま貼る。

## 2. 2件目以降のチャットに貼るプロンプト（定型）

前のチャットが最後に出力した引き継ぎプロンプトを貼るのが基本。手で書く場合はこの型を使う。

```
このリポジトリ（yorucare）の開発を、1チャット1タスクで順番に進めています。あなたは <N> 件目を担当します。

前のチャットの成果
- ブランチ: <ブランチ名>
- コミット: <コミットハッシュ> <コミット件名>
- 完了タスク: <前のタスク名>
- 引き継ぎメモ: docs/handoff/latest.md

やること
1. git pull で最新を取り込み、docs/handoff/latest.md と docs/DEVELOPMENT_BOARD.md を読む。前のチャットの申し送り（未解決事項・注意点）を先に確認する。
2. AGENTS.md と、今回のタスクに関係する docs/ 配下の決定事項を読む。
3. 今回のタスク「<タスク名>」だけを実装する。
4. pnpm lint / pnpm test / pnpm build を通す。
5. docs/DEVELOPMENT_BOARD.md の該当行を更新する。
6. docs/handoff/latest.md を今回の内容で書き直す（追記ではなく上書き。過去分は docs/handoff/<YYYY-MM-DD>-<連番>.md へ退避する）。
7. コミットして push する。
8. 次のチャットにそのまま貼れる引き継ぎプロンプトを、コードブロックで出力する。

守ること（前チャットと同じ）
- 記録本文や個人を特定できる情報を、管理表・引き継ぎメモ・コミットメッセージに書かない。
- スキーマを変える場合は移行と読み込み互換を用意する。
- 1チャットで2件以上のタスクを進めない。範囲外の改善は管理表に1行足すだけにする。
- 実機確認や利用者確認が必要なタスクは、実装ではなく確認手順の整備までに留め、進捗を `確認待ち` にする。
```

## 3. 引き継ぎメモの書式（`docs/handoff/latest.md`）

```markdown
# 引き継ぎメモ

- 日付: YYYY-MM-DD
- 担当チャット: <N> 件目
- ブランチ: <ブランチ名>
- コミット: <ハッシュ> <件名>

## 今回やったこと
- 対象タスク（管理表の課題名）
- 変更したファイルと、その変更が何を実現したか（1行ずつ）

## 検証結果
- pnpm lint / pnpm test / pnpm build の結果
- 追加したテストと、そのテストが守っている条件

## 決めたこと
- 実装中に判断した仕様と、その理由

## 積み残し・次のチャットへの申し送り
- 未解決の課題、触ると危ない箇所、次に着手すべきタスク名
```

---

## 4. 運用上の注意

- 引き継ぎはチャットの記憶ではなくリポジトリ内のファイルで行う。`docs/handoff/latest.md` を書かずに終えたチャットは、次のチャットが前提を失う。
- 管理表の `判断済み` 行にある「本棚演出の方向性確定前には着手しない項目」は、記録完了演出まわりの作業に対する制約として扱う。目標機能など別タスクで `DailyRecord` を拡張する必要が出た場合は、演出の制約とは切り離して、スキーマ移行の可否を先に判断する。
- 1タスクが大きすぎてチャット内で終わらないときは、途中でコミットし、進捗を `進行中` のままにして引き継ぎメモへ残りの手順を書く。無理に完了へ変えない。
