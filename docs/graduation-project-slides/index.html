「今月、調子はどうですか」

障がい者採用で働いている方に、体調を伺いました。

返ってきたのは、
自分がいまどういう体調で、何を相談したいのかが、
分からない、という状態でした。

その面談で起きたこと

60分の面談のうち、
日誌の確認だけで20〜30分

1回の面談（60分）の使われ方
体調の確認（日誌を一つ一つ）
20〜30分
対策・職場環境の配慮
ここまで届かない

60分の面談のうち、半分が、状態を聞き出すことに消えました。
肝心の、対策や、職場環境の配慮を考えるところまで、いけなかったんです。

AI DRIVEN SCHOOL ／ 卒業制作 企画発表

私は、精神障害と向き合う方の、復職後の職場復帰・就労継続をサポートしています。
卒業制作で伸ばすのは、セルフケア記録アプリ「ヨルケア」です。

あいまいな記憶を材料にしていたやりとりを、
渡せる事実に変える

Phase 1 MVP は稼働中 卒業制作で作るのは、数値化・要約・渡すこと
https://yorucare.vercel.app
なぜ、こうなるのか 1／2

治療にもリワークにもある「ものさし」が、
職場に戻ったあとにはない

医療 うつ症状 → 治療 症状を見る共通のものさしがある
→
リワーク 復職の準備 課題を見る共通のものさしがある
→
企業 ／ わたしの持ち場 職場復帰 → 就労継続 ものさしがない

あのとき、心の中ではこう思っていました。体調が良いのか、悪いのか、分からない。本当に問題ないのか、判断ができない。だから、聞くしかない。聞くために時間がかかって、配慮の話まで届かない。

なぜ、こうなるのか 2／2

判断材料は、この2つだけ

本人の自覚

「なんとなくしんどい」。しんどい時期ほど、崩れた起点を思い出せません。

周囲が見た様子

見えるのは日中の一部だけ。夜と休日は、ほとんど含まれていません。

現場の声：復職後1〜2ヶ月で体調管理の記録が途切れ、
そのあと、不調が出る。

記録が途切れること自体が、問題の中心ではありません。続かない記録は、相談の材料にならない。そこがいちばん痛いところです。既存アプリは服薬特化が多く、体調の波・生活リズム・できたことを一体で扱えません。連続記録を褒める設計は、書けない日が続いた人ほど戻ってこられなくします。

どうやって 1／3

やり方は、3つです

毎日 ／ 1〜2分 記録する 気分・睡眠・お薬・しんどさのサイン・できたこと
→
週ごと 要約する 本人が選んで、渡せる短い文章にする
→
月に1回 K6で数値化する 国の調査で使われる6つの質問。0〜24点。毎回同じ質問なので変化が見える

自分に対して

状態を俯瞰でき、セルフケアの判断に使える。

相手に対して

医療従事者・支援者・職場内サポーターへ、端的にすぐ伝えられる。

先に言います。K6の点数で「危ない」と判断したり、受診を勧めたりはしません。本人と周囲が、同じ数字で変化を見るためのものさしです。

どうやって 2／3

設計でいちばん大事なのは、4点

1. 記録は本人の端末にだけ残す

自動送信しない。運営も勤務先も見られない。評価される記録になった瞬間、人は正直に書かなくなるからです。

2. 書けなかった日を、失敗として表示しない

連続記録を強調せず、中断後にまた書けたかを指標にします。

3. 数値はアプリが確定させる

AIには書き換えさせない。0件のときは0ではなく「データがない」を返し、「低い」と混同させない。

4. アプリで抱え込ませない

しんどさが強いときは相談窓口へ渡します。診断も助言もしません。

どうやって 3／3

卒業制作期間の山場は、この4つ

作るもの完成の判断
1入力を削る
「よい／ふつう／しんどい」を選ぶと、追加の質問が必要な分だけに絞られる		5人中4人以上が2分以内に保存できる
2K6と、その推移
毎回まったく同じ6つの質問。0〜24点と、前回からの変化		点数の判定・受診勧奨をアプリ側で行わない
3まとめの言語化
数値はアプリが埋め、文章の穴だけをAIが書く「穴埋め方式」		AIが数値を書き換えられない構造になっている
4渡す導線
最大7日分・本人が選んだ項目だけをテキスト化		全文を本人が確認してからでないと、端末の外に出ない

同時に入れると何が効いたか分からなくなるので、1つ入れて、観測して、次を決めます。

どうなるのか

あの月次面談が、こう変わります

いま ／ 60分
体調の確認 20〜30分
対策・配慮 ここまで届かない
記録・要約・K6があると ／ 60分
状態の共有
3分
残りの約57分を、配慮と対策の話に使える

作って終わりにしないため、やめる基準も先に決めてあります。2週目に戻れたか、4週目まで使えたか、中断のあとにまた書けたか。これはアプリの使いやすさを見る指標で、症状が良くなったかを示すものではありません。

みなさんに聞きたいこと

方向性を固めたくて、持ってきました

  1. 「入力を削る → K6 → まとめ → 渡す」の順番で合っているか。
    先に作るべきものが、ほかにありませんか。
  2. 書けない日が続いた人が戻ってくる仕掛けとして、通知以外に思いつくものはありますか。
  3. みなさんの職場に置き換えたとき、この記録を見せられる相手は誰ですか。

ヒアリングで確認できた事実

聞いた相手確認できた事実
当事者A夜のSNS閲覧が常態化し、睡眠不足から不調を招く
当事者B会社には相談しにくい。支援面談は月1回。自作のExcelで、孤独に体調管理をしている
支援員復職後1〜2ヶ月で体調管理の記録が途切れ、そのあと不調が出る。面談は仕事ができているかの確認で精一杯で、生活面まで踏み込む時間がない

いま動いているもの（Phase 1 MVP）：4タブ構成、期間別グラフ、直近7日の週次まとめ、記録のファイル保存・復元、全タブ共通の相談窓口導線。集計を確定させる層は実装済みです。

補足（質疑用・発表では飛ばす）

あえて作らないと決めたもの

作らないもの理由
記録本文の自動クラウド保存現在の参加説明が「本人端末内・運営は閲覧しない」。変えるには同意と研究手続きの取り直しが必要
勤務先・支援機関への自動共有記録が評価材料になった時点で、本人が正直に書けなくなる
通知によるリマインド継続率が低いことだけを理由に作らない。「忘れる」が非継続理由の30%以上を占めたときだけ着手する
K6の点数による重症度判定・受診勧奨数値化は本人と周囲が変化を見るためのもの。判定は医療の役割で、アプリが肩代わりしない
症状の判定・助言診断・治療の代替にしない。ガイドラインの推奨を製品の効能として主張しない
補足（質疑用・発表では飛ばす）

AIに渡すもの、渡さないもの

渡すもの

  • アプリが確定させた集計値（母数つき）
  • 選択式のタグ
  • 「できること」辞書のタイトル

渡さないもの

  • 本人が書いたメモの本文
  • 服薬・面談に関する記述
  • 個人を特定できる情報

これは運用ルールではなく、戻り値の型に本文のフィールドを持たせないことで保証しています。うっかり渡すことが、そもそもできません。
