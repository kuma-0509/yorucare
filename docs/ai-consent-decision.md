# AI機能の同意方針とツール設計の判断

決定日: 2026-08-01
状態: 集計値のみを外部へ出す方針で確定・集計ツール層を実装開始

## 1. 結論

AI機能が外部のLLM APIへ渡してよいのは、アプリ側で確定させた集計値・タグ・「できること」のタイトルだけとする。本人が書いた本文（`note` / `warningNote` / `selfCareMemo` / `tomorrowGoal`）は端末外へ出さない。

この方針は運用ルールではなく型で保証する。集計ツールの戻り値型に本文のフィールドを置かないことで、後から誤って本文を渡す実装ができないようにする。

本文ではないが同じく渡さないものが1つある。積み重ね表示の起点として本人が設定する復職日（`DailyRecord` ではなく `STORAGE_KEYS.returnDate` に持つ）は、選択式であっても休職と復職という職歴上の事実を1つの日付で示す。集計値ではないため、3節の表のとおり外部へ渡さない。

## 2. なぜ集計値のみか

- 報告先が支援者と医師であり、数値の誤りが本人の不利益に直結する。数える・並べる・絞るはすべてアプリ側の仕事とし、LLMには言語化だけをさせる。報告書は穴埋め方式で、数値の穴はアプリが埋める。
- メモ本文を送るには、既存の匿名利用イベントより一段重い個別同意UI、撤回導線、保存期間の設計が必要になる。集計値のみであれば報告書と「できること」提案は成立するため、実装を先に進められる。
- `docs/sharing-decision.md` は、15名の非商用フィードバック期間には特定の生成AI APIへの自動送信を本番実装しないと定めている。本方針はこれと矛盾しない。今回実装するのは送信を伴わない集計層であり、LLM呼び出しの本番投入は同文書のGateに従う。

## 3. 送ってよいもの・送らないもの

| 種別 | 外部LLMへ渡す | 理由 |
| --- | --- | --- |
| 集計値（平均、分布、日数、割合） | 渡す | アプリ側で確定済みで、本人を特定しない |
| `warningTags` | 渡す | 選択式の語で、本人が書いた文章ではない |
| 「できること」辞書のタイトル | 渡す | 提案を辞書の範囲内に限るために必要 |
| `moodLabels` | 渡す | 選択式のラベル |
| `goalReviewStatus` | 渡す | 選択式の達成状況。3段階から選んだ結果で、本人が書いた文章ではない |
| `selfCareFeeling` | 渡す | 選択式のセルフケアの感想。3段階から選んだ結果で、本人が書いた文章ではない |
| `note` / `warningNote` / `selfCareMemo` / `tomorrowGoal` | 渡さない | 本人が書いた本文。型に持たせない |
| 復職日（`STORAGE_KEYS.returnDate`） | 渡さない | 選択式ではあるが、休職と復職という職歴上の事実を1つの日付で示す。集計値ではなく本人の状況そのものなので、`DailyView` にも `PeriodSummary` にも入れない |
| 日付そのもの | 期間の端だけ渡す | 日単位の全履歴は再識別性を上げるため、集計に畳む |

本人が自分の判断で本文を外部AIへ渡したい場合は、既存の共有テキスト機能（`src/lib/ai-share-text.ts`）を使う。こちらは本人が全文を確認したうえで自分で貼り付ける経路であり、アプリからの自動送信ではない。両者を混同しない。

## 4. `summarizePeriod` の戻り値で決めたこと

実装は `src/lib/ai/period-summary.ts`。

- **`recordedDays` を必ず返す。** 母数がないと、記録できないほどしんどかった期間がデータ上「平穏な期間」に見える。`daysInRange`（暦日数）と別に返す。
- **対象が0件のとき平均は `0` ではなく `null`。** `0` を返すとLLMが「気分が最低だった」と読む。「データがない」と「値が低い」を型で区別する。
- **項目ごとに母数を別々に返す。** `scoredDays` / `measuredDays` / `bedtimeDays` / `answeredDays` を個別に持つ。共通の `recordedDays` だけだと、LLMが誤った母数で割合を語る。
- **就寝時刻は平均ではなく中央値を、正午を基準とする窓で計算する。** 日をまたぐため単純平均が壊れる（23:00 と 01:00 の平均が 12:00 になる）。
- **割合は `donePercent` として0〜100の整数で返す。** 割り算をLLM側に残さない。
- **キー名に「効果」「effect」を使わない。** LLMは渡された言葉に引きずられ、相関を因果として断定する。事実だけを述べる名前にする。

## 5. 残りのツールで決めたこと

実装は `src/lib/ai/` 配下。集計は純関数として置き、保存先からの読み出しと `Result` 境界の受け渡しだけを `tools.ts` が担う。保存先が API に変わっても集計の実装は変えずに済む。

### 「期間内の生の記録」を返すツールは作らない

引き継ぎ時の設計にあった `getRecords(from, to)` は、そのまま実装すると本文を含む記録を外へ出すことになり、本方針を破る。代わりに本文を持たない `DailyView` を返す（`daily-view.ts`）。メモについては `hasMemo` として有無だけを返し、本文は渡さない。

記録がない日も `recorded: false` として返す。記録がある日だけを返すと、記録できないほどしんどかった日が期間そのものから消え、LLMが「その期間は何もなかった」と読む。

### 連続日数は未記録日で途切れさせる

`findStreaks`（`streaks.ts`）は期間内の全日を1日ずつ走査し、記録がない日は条件を満たさなかったものとして連続を切る。記録がない日を満たしたことにすると、記録できなかった期間が「好調が続いた期間」に化ける。連続が切れた理由を区別できるよう `unrecordedDays` も返す。

条件は自由な式ではなく閉じた集合（`StreakCondition`）にする。任意の条件を受け取れるようにすると、何を数えたのかを説明できない切り口が作られる。

### 頻度集計は並びを固定する

`listWarningTags` / `listSelfCare`（`frequency.ts`）は日数の降順、同数なら名前の昇順で並べる。並びが入力順で変わるとLLMの出力もぶれる。同じ日に同じ語が重複していても1日として数える。母数として `recordedDays` を返す。これがないと「3日に出た」が多いのか少ないのか判断できない。

### 実行日と非実行日の差分は、少ない日数では出さない

`relateSelfCareToMood`（`self-care-relation.ts`）はキー名に「効果」「effect」を使わず、`differenceInAverage` のように事実だけを述べる名前にする。片側の日数が `MIN_DAYS_FOR_COMPARISON`（3日）を下回る場合は差分を `null` にする。1日や2日の差を並べると、LLMも本人も意味のある傾向として読んでしまう。

非実行日の母数は「期間内のすべての日」ではなく「記録がある日」にする。記録がない日を非実行日に含めると、記録できなかった日が「セルフケアをしなかった日」として数えられる。

### 書き込み系のツールは用意しない

`tools.ts` に置くのは読み取りだけとする。LLMに保存・削除の手段を渡さず、下書きまでに留めて確定は本人のボタン操作にする。

### 毎回同梱するもの

直近7日の `DailyView` と「できること」辞書は `buildRecentContext()` でまとめて渡す。ほぼどの問いでも必要になるうえ量が小さく、都度ツールで取りに行かせると往復が増えるだけ。1か月以上の長期データと集計値は、必要なときだけツールで取りに行かせる。

## 6. 週次まとめで決めたこと

実装は `src/lib/ai/weekly-summary.ts` と `src/components/reflection/weekly-summary-card.tsx`。

### LLMを呼ばない

週次まとめは毎週同じ切り口で読むものなので、言い方が週ごとにぶれるほうが本人にとって不安になる。定型ルールだけで組み立て、速く、無料で、毎回同じ言葉になるようにする。集計は既存のツール層に任せ、この層は並べ方と言い方だけを決める。数値を自前で計算しないことで、画面と共有テキストで数字がずれない。

### 表現の制約

文面の制約は表示側ではなく生成側の責任とし、テストで固定する。

- 記録がなかった日を「抜けた」「できなかった」と書かない。「7日中2日」「5日は記録がありません」も使わない。記録できないほどしんどかった日を、本人の失敗として提示しない。
- 評価語（よい、悪い、改善、悪化）と助言（〜しましょう）を出さない。判断は本人と支援者・医師が行う。
- 数値には必ず母数を添える。3日分の平均を7日分の傾向として読ませない。
- 割合ではなく日数で示す。「達成率67%」は達成できなかった側を強調する。服薬は「できた2日」と数え、忘れた日数を項目として並べない。
- 空状態は「記録がありません」で終わらせず、次に書くときの負担を下げる一文を添える。

### 生成条件と共有形式

対象は直近7日で、記録の入力範囲と揃える。記録が0日でも表示し、空状態の文面へ分岐する。分岐の判断は `isEmpty` として生成側が返し、表示側は薄く保つ。

共有は端末内でプレーンテキストを組み立ててコピーするだけで、どこへも送信しない。渡す先を選ぶのは本人の操作で、既存の共有導線と同じ扱いにする。まとめには必ず「診断や治療の判断には使えません」を添える。

### 目標のふりかえりは選択式だけを数える

目標機能（`tomorrowGoal` / `goalReviewStatus`）の実装後、週次まとめに「目標のふりかえり」の行を追加した。数えるのは選択式の `goalReviewStatus` だけで、本人が書いた目標の文面（`tomorrowGoal`）は `PeriodSummary` にも `WeeklySummary` にも持たせない。本文を型に持たせないことで保証する1節の方針を、そのまま適用している。

表示は服薬と同じ形にする。「できた N日」と日数で示し、母数を添え、できなかった日数は項目として並べない。割合（達成率）は出さない。

### 自分メンテの感想も選択式だけを持つ

自分メンテ（`src/lib/self-care.ts`）の実装で `DailyRecord` に `selfCareFeeling` を追加したが、感想は選択式の3段階だけとし、自由記述のフィールドは作っていない。本文を増やせば、それを外へ出さないための保証を型で足し続ける必要が生じる。既存の自由記述（`selfCareMemo`）はそのまま残り、扱いも変わらない。

`selfCareFeeling` は3節の表のとおり渡してよい値だが、現時点では `DailyView` にも `PeriodSummary` にも入れていない。利用側が決まっていない段階で戻り値型を広げないため。渡す必要が出た時点で、利用側と併せて判断する。

なお自分メンテの提案自体は、外部へ何も渡さない。入力は `StateLevel` と `warningTags`（どちらも選択式）だけで、生成は端末内の定型ルールに閉じている。

## 7. 積み重ね表示で決めたこと

実装は `src/lib/ai/milestones.ts` と `src/components/reflection/accumulation-card.tsx`。週次まとめと同じく、LLMを呼ばず外部通信もしない。節目のねぎらいは毎回同じ言葉になるほうがよく、言い方が日によってぶれると本人にとって不安になる。

### 起点は端末内の設定として持ち、外部へは渡さない

起点は `DailyRecord` ではなく `STORAGE_KEYS.returnDate` に持つ。日々の記録ではなく本人が一度決める設定であり、記録へ持たせると日ごとに違う値を持ててしまう。書き出し・取り込みの対象には含める（機種変更で起点が失われないため）。既定値を持つ任意フィールドとして追加したので、`EXPORT_VERSION` は1のまま据え置き、復職日を持たない既存の書き出しもそのまま読める。`DailyRecord` を変更していないため `STORAGE_SCHEMA_VERSION` も3のまま据え置く。

未設定のときは最初の記録日を既定の起点にする。何も設定しなくても表示が成立し、設定した時点で本人の選んだ起点へ切り替わる。

### 連続記録を主役にしない

`docs/phase2-plan.md` 2節の「未入力や中断を失敗として扱わず、連続記録だけを評価・強調しない」に従い、次を生成側の制約として固定する。

- 上に置くのは中断で減らない累計（記録した日・できたことがあった日）とし、連続は最長を1行だけ最後に添える。
- **「いま何日続いているか」は出さない。** 1日空けた翌日に数字が1へ戻る表示は、書けなかった日を目に見える損失として示すことになる。
- 節目は記録日数の累計と起点からの経過日数だけに置き、連続日数を節目にしない。どちらも中断で減らないため、書けない期間があっても節目が失われない。
- 数えるのは起点以降だけとする。起点を動かしたときに数字の意味が変わらないようにするため。

### ねぎらいは届いた日だけ、評価語を出さない

節目のねぎらいは、その値にちょうど届いた日だけ出す。過ぎた節目を毎日祝うと言葉が軽くなる。

**「節目ちょうどの値かどうか」だけで判定しない。** 記録した日の累計は新しい記録がなければ動かないため、その条件だけだと、節目に届いたあと記録しない日が続くかぎり同じ言葉が出続ける。累計を今の値へ届かせたのは範囲内でいちばん新しい記録なので、それが今日のものであるときだけ「今日届いた」とする。数日前の日付をあとから記録して節目に届いた場合はねぎらいを出さない（届いたのはその記録の日付の話であり、今日ではない）。経過日数は毎日1つ増えるので、節目ちょうどの値になる日はもともと1日しかない。

文面は届いた事実と「おつかれさま」だけにし、「すごい」「順調」（本人の状態への評価になり、書けなかった日を裏返しに評価する）と「この調子で」「続けましょう」（助言であり、次を求めることになる）を出さない。禁止語の一覧は `src/lib/ai/milestones.test.ts` と `src/components/reflection/accumulation-card.test.tsx` に置き、表示テストで固定する。
