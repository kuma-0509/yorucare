# リマインドの導入判断と最小構成

決定日: 2026-07-26  
状態: 要件確定・Gate 2の判定まで本番実装を保留

## 1. 結論

15名の非商用フィードバック期間には、リマインドを本番実装しない。`docs/phase2-plan.md`のGate 2に従い、「忘れる」または「始めるきっかけがない」が、確認できた回答の30%以上を占めるかを先に確認する。

現在のヨルケアには、PWAマニフェスト、Service Worker、Push購読、時刻別の配信処理がない。Webページ内のタイマーだけでは、ページを閉じた後やOSが処理を停止した後の通知を保証できない。実際に利用開始のきっかけとなる通知を検証するときは、端末を閉じていても届くWeb Pushを使用する。

Vercel HobbyのCronは1ジョブにつき1日1回までで、実行時刻にも最大約1時間の幅がある。利用者が選んだ時刻へ安定して配信する条件に合わず、非商用期間はVercel Proを契約しない方針でもあるため、Gate 2未達の現在は通知基盤を作らない。

## 2. Gate 2の判定方法

15名へのフィードバックでは、実際の記録内容や自由記述を収集せず、次の固定選択だけで非継続理由を確認する。回答しない選択も認める。

質問:

> 記録しなかった日や、再開しにくかったときに当てはまるものを選んでください。（複数選択可）

- 忘れていた
- 始めるきっかけがなかった
- 時間や余裕がなかった
- 入力することが負担だった
- 記録する必要を感じなかった
- 当てはまるものはない
- 回答しない

判定規則:

1. 分母は、上記のうち「回答しない」以外を1つ以上選んだ人の数とする。
2. 分子は、「忘れていた」または「始めるきっかけがなかった」の少なくとも一方を選んだ人の数とする。同じ人が両方を選んでも1人と数える。
3. `分子 ÷ 分母`が30%以上ならGate 2を満たす。15人全員が有効回答した場合は5人以上が該当する。
4. 30%未満、または判断に足りる回答が集まらなければ、リマインドは実装せず端末内保存の現行構成を維持する。
5. この結果は通知需要の判断にだけ使い、医学的効果の根拠として扱わない。

## 3. Gate 2通過後の最小構成

| 領域 | 最小構成 |
| --- | --- |
| 通知手段 | PWAのService Workerと標準Web Push。メール、SMS、LINE、端末カレンダー連携は初期対象外 |
| 初期状態 | OFF。OSの通知許可を自動で要求しない |
| 有効化 | 本人が設定画面でONを選び、ロック画面へ表示されることを確認した後の明示操作で通知許可を要求する |
| 時刻 | 本人の端末時刻で1日1回、`input type="time"`により設定する。初期表示は21:00だが、ONにするまで保存・配信しない |
| 頻度 | 1日1回だけ。曜日、複数時刻、連続通知、未記録時の追通知は初期対象外 |
| 停止 | 設定画面からいつでもOFFにできる。OFF時はPush購読を解除し、サーバー上の購読情報を削除する |
| 期間 | 小規模検証では有効化から28日で自動停止し、無期限に通知し続けない |
| 通知操作 | 通知を開くとヨルケアの「今日の記録」へ移動する |
| 許可拒否 | OFFのままとし、同じ利用中にOS許可を繰り返し要求しない。OS設定から変更できることだけを案内する |
| 対応外端末 | 利用できないことを表示し、通知できるように見せない |

iPhone・iPadでは、ホーム画面へ追加したWebアプリだけを対応対象とする。通知許可は、本人がボタンを押した直後にだけ要求する。

## 4. 通知文

通知は、ロック画面で他者に見られる可能性を有効化前に説明する。本文へ記録の有無、状態、服薬、面談、目標などを含めない。

- タイトル: `ヨルケア`
- 本文: `よければ、今日のことを少しだけ振り返ってみませんか。`

「まだ記録していません」「連続記録が途切れます」など、未記録を責める表現は使用しない。症状や状態を推測する表現、入力を求める命令形、緊急性を示す表現も使用しない。

## 5. データ境界

Push購読情報は、本人の記録本文、匿名利用イベント、研究データ、将来のアカウント情報と分離する。

保存を許可する情報:

- Pushサービスが発行した購読先と公開鍵
- ランダムな`reminderId`
- 本人が選んだ時刻とタイムゾーン
- 有効期限
- 配信成否と、無効な購読先を削除するための最終確認日時

保存しない情報:

- 記録本文と記録項目
- 記録したかどうか
- 健康、服薬、面談、勤務に関する情報
- 匿名分析の`installId`とその不可逆化値
- 氏名、メールアドレス、電話番号

通知OFF、28日の有効期限、Pushサービスからの`404`または`410`応答のいずれかで、購読情報を削除する。配信ログには通知本文や端末識別子を残さず、成功・失敗件数だけを運用集計する。

## 6. 実装開始条件

次をすべて満たすまで、マニフェスト、Service Worker、Push API、購読API、配信DB、VAPID鍵、時刻別Cronを本番へ追加しない。

1. Gate 2の固定選択フィードバックが30%以上になる。
2. 本人が通知内容、時刻、ロック画面表示、停止方法を理解できる画面案がレビュー済みである。
3. Push購読情報の保存場所、暗号化、削除、運用権限、事故対応を確認する。
4. iPhoneとAndroidで、ホーム画面追加、許可、受信、通知タップ、停止、自動終了を実機確認できる。
5. 選択時刻に必要な頻度・精度で配信できる契約または代替スケジューラーを承認する。
6. 配信失敗時に再送を重ねず、重複通知を防ぐ設計とテストを用意する。

## 7. 受入テスト

- 初期状態がOFFで、初回表示だけではOSの許可画面が出ない。
- 本人の操作なしに通知購読を作らない。
- ON、時刻変更、OFFがキーボードと画面読み上げで操作できる。
- 固定文面以外の情報が通知と配信要求へ入らない。
- タイムゾーンと夏時間を含め、選択時刻に1日1回だけ配信される。
- 同じ配信を再実行しても重複通知にならない。
- OFF後と28日後に通知が届かず、購読情報が削除される。
- 許可拒否、Push非対応、オフライン、無効購読先をエラーとして扱い、ONと誤表示しない。
- iPhoneではホーム画面追加前に通知を有効化できるように見せない。
- 通知を開くと「今日の記録」が表示される。

## 8. 採用しない方式

| 方式 | 採用しない理由 |
| --- | --- |
| ページ内の`setTimeout`だけで予約する | ページ終了やOSによる休止後の配信を保証できない |
| Periodic Background Syncだけで予約する | 対応ブラウザが限定され、実行時刻も保証されない |
| メール、SMS、LINE | 連絡先や外部アカウントを新たに扱い、最小検証のデータ境界を広げる |
| カレンダーファイルの取り込み | アプリのOFF操作で取り込んだ予定を確実に削除できない |
| 記録の有無に応じた通知 | サーバーへ記録状態を送る必要が生じ、端末内保存の境界を崩す |
| Vercel Hobbyの1日1回Cron | 利用者ごとの選択時刻に必要な頻度と精度を満たさない |
